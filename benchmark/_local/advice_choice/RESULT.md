# 教诲分配实测：搜索档 vs 配置预设（2026-11-13）

## 1. 口径

- 问题：配置 `[decks.default.advice]` 给了 6 个窗口的手写落位预设，但搜索档
  （`[search].advice = true`）实际选出来的分配与它差多少、差在哪。
- 两档卡组 = 基线同款：`a-normal`（105902，无 buff）/ `b-ideal`（106302，小切 + 心情盾 2），
  默认卡组（1 耐位 `30324`）、`[decks.default]` 参数、`pt_score_rate = 1.88`。
- 每档 **10 局**，seed0 = 73200（与基线同块），搜索 **N = 2048**；决策流种子 = 规则主种子，
  推进序与 `bench` 的 `play_with_engine` 相同。同日同局另跑手写档作参照。
- 统计对象 = 6 个教诲窗口（T2 / T11 / T35 / T59 在 Begin，T23 / T47 在 End）最终生效的
  **有效 id**（融合后优先），与 `preset_advice_ids(window)` 同口径**逐位**比较
  （位 = 演目 速/耐/力/根/智）。「可行」= 该窗口 120 个候选里存在与预设等价的方案。

复跑（release，约 4.5 分钟）：

```powershell
$env:MATSURI_ADVICE_GAMES='10'; $env:MATSURI_ADVICE_N='2048'
cargo test --release --offline -p matsuri-core --test diag_advice_choice -- --ignored --nocapture
```

原始输出：同目录 `raw_2048.txt`（`benchmark/_local/` 不入库）。

## 4. 主导布局

`a-normal`（预设 → 搜索最常见）：

| 窗口 | 预设（有效 id） | 搜索实际 |
|---|---|---|
| T2 | 牵绊/擅长率/体力/灵感/助力 | 助力/擅长率/体力/灵感/牵绊 ×4（助力 `401` 上速、牵绊 `101` 下智）；另一种 牵绊/助力/体力/灵感/擅长率 ×3 |
| T11 | 牵绊/体力/擅长率/灵感/助力 | 3 种各 ×2（牵绊/体力/擅长率/灵感/助力、牵绊/体力/助力/灵感/擅长率、体力/牵绊/擅长率/灵感/助力） |
| T23 | 特化/助力/体力/灵感/研习 | **研习/特化/体力/灵感/助力 ×9**：特化 `601` ↔ 研习 `701` 系统性对调（速 0/10、智 0/10） |
| T35 | 特化/体力/灵感/助力/研习 | 研习/体力/特化/助力/灵感 ×3 等 5 种，无主导 |
| T47 | 特化/协助/兼修/不屈/研习 | 协助/兼修/特化/不屈/研习 ×6（协助 `801` 被硬约束顶到速） |
| T59 | 协助/兼修/特化/不屈/研习 | 完全一致 ×10 |

`b-ideal` 形态相同：T23 研习打头（7/10 以 研习 开头）、T47 协助 必在速、T59 完全一致；
T2/T11/T35 分散（各 5–7 种布局）。

**T47 的预设本身不可行**：`t47 = [101,501,401,301,201]` 融合后是 特化/协助/兼修/不屈/研习，
把协助 `801` 摆在耐位；但 `401+801` 硬约束要求 `801` 落在**担当数最多的演目**（当前卡组是速），
所以 120 个候选里没有任何一个能等于预设（可行 0/10）。手写档因此落在 协助/特化/兼修/不屈/研习，
搜索档落在 协助/兼修/特化/不屈/研习——两者都只是在「协助已占速」的前提下重排。

## 5. 结论

1. **配置预设 ≈ 手写档行为**（5 个窗口 10/10 全中），说明 `route = 392` 的落位先验在手写估值里
   足够强；T47 例外是不可行，不是先验失效。
2. **搜索档基本不认这份预设**：T2/T11/T23/T35 命中 0–2/10，差异是纯「演目→教诲」重排
   （同一组 5 个教诲换位），平均每窗换 2–3 个位置。
3. 分歧集中在 **速 / 耐**（特化 / 研习 / 助力 的归属）；根位几乎不动，T59 完全收敛。
4. 若希望搜索档也贴近攻略落位，方向是调 `[decks.default.trainer.advice].route`（或按窗口给
   搜索档单独预设），而不是只改 `[decks.default.advice]`——后者对搜索只通过 route 先验起作用，
   当前强度不足以压过 N=2048 的 rollout 估值。
5. `t47` 建议按 `801` 硬约束重写（把协助挪到速位），否则该窗口的预设在两边都只是摆设。

把 T2 / T11 / T23 / T35 的预设换成第 4 节里搜索的**众数布局**（`t47` 同时按 §4 的硬约束修正），

### 7.3 判读

1. 预设在这里的作用是**候选准入**，不是偏好：教诲决策只有 120 个候选取手写估值 top-16 进搜索
   （`ADVICE_TOPK = 16`）。改预设 = 改搜索能看见的 16 个候选，所以确实会影响搜索决策
   （样本内 10/10 全都变了），但收益不可复现。
2. 因此「按搜索结果改手写预设」是**确定的损失换不确定的收益**：手写 −334 / −134 是实打实的，
   搜索 +210 ~ +275 站不住。
3. 唯一值得做的是 **`t47` 修正**：手写 3000/3000、搜索 10/10 完全不变（不可行预设本来就
   命中 0 格、对估值无贡献），只是把文档口径改成硬约束允许的落位。
   **2026-11-13 已落地**：`data/matsuri_config.toml` 与 `AdvicePreset::default()` 同步为
   `t47 = [501, 101, 401, 301, 201]`；复验 = 两档手写基线 100 局 Δ0、seed 61444 冒烟
   84866 / PT 11845 不变、T47 可行性 0/10 → 10/10（手写命中 10/10）。
4. 若目标是让搜索也走攻略落位，正确杠杆是 `route` 权重或搜索档专用预设，且验收必须用
   **留出种子块**——本轮就是范例：样本内 +1155 → 留出 +212。
