## 1. 回合与阶段

> 口径：本文 turn 一律 **0 基**（`turn ∈ [0, 77]`）；`master.mdb` / 游戏内显示为 1 基，必要时在括号内保留原始值。

- 回合范围：`turn ∈ [0, 77]`（全 78 回合）；Senior 10 月後半最终结算在 `turn 67`。
- 三次剧本结算 / 進捗発表会：`turn 23 / 47 / 67`，门槛全演目 Lv `3 / 5 / 6`
  （`single_mode_15_schedule`；`need_act_num = 5`）。
- 合宿窗口：`turn 12–15 / 36–39 / 60–63`（0 基；Junior 即有夏合宿）。
- **合宿规则**（官方帮助）：合宿中**每回合都能进行演目稽古**；合宿中**演目 Lv 不上升**；
  合宿结束后**全演目 Lv +1**；合宿中无体力回复事件（「不回体」仅指没有合宿内回体事件）。
- **合宿延长**（user 实测 2026-10-26）：基础 4 回合；若合宿窗口内出现目标比赛或强制休息，
  合宿按回合顺延，直到该年累计 **4 个非比赛合宿回合**。比赛回合与强制休息回合不计入这 4 个。
  - 例：樱花进王顺延到 10 月前半（0 基 turn 66）；凯斯奇迹 9 月前半比赛、9 月后半比赛触发强制休息，
    10 月前半仍有顺延合宿回合。
  - **全演目 Lv +1** 的结算点**暂定固定为该年 8 月后半结束（turn 15 / 39 / 63 结束时）**，
    不随顺延推迟；视频「3 个演目各 +1」按样本截断，不采用。
  - **延长回合属性（U18，2026-10-31）**：**所有年份的延长回合都算合宿（全部为排练）**；
    第 1 年的延长回合也按第 1 年合宿规则（正常休息 / 可外出 / 可有支援卡事件）。
  - **延长段事件轴（U19，user 2026-11-03）**：**等同正常回合**——支援卡连续 / 普通马娘 / 掉心情等
    随机事件均可触发，仅训练全变演目稽古；第 2/3 年常规 4 回合的无事件抑制不延伸到延长段。
  - **离线模拟口径（2026-10-31）**：本阶段只做离线模拟，只需与在线行为一致，不依赖在线数据下发；
    合宿窗口与所有年份的延长回合按**硬编码**判定，`summer_camp_remain_turn_num` 只作对照。
- **合宿外出 / 休息（U33，2026-10-31；休息范围 2026-11-01 细化）**：**第 2/3 年合宿不能普通 / 友人外出**；
  **合宿版休息只在原本夏合宿期间＝Classic/Senior 的 7–8 月，延长回合休息为普通休息**
  （`shuntaisai_memo` 2026-10-31；外出仍按 U33 全程不可，含延长段）；
  **第 1 年正常休息，可普通 / 友人外出，可有支援卡事件**。
- **合宿期事件**（user 2026-10-30；延长段 2026-11-03 确认）：**第 1 年**合宿支援卡连续事件 + 普通马娘事件都发生；
  **第 2/3 年**常规合宿回合两类都不发生；**延长段事件轴等同正常回合**——支援卡连续 / 普通马娘 /
  掉心情等各种随机事件均可触发，仅训练全变演目稽古（U19 结项）。**抑制表由剧本自持**：合宿规则层
  只盖第 2/3 年常规窗口，延长段回落引擎 `no_event_turns` 基线（见 §5.3 / §5.4）。
- 本番后：剧情结束，先进入 **68–71 的空窗期**（剧本已结束、尚未进 URA；按日常机制），
  **72–77 才是 URA 回合**。**URA 期全变演目稽古（类似合宿，2026-11-04 确认）**：5 个训练位全部
  `ActTrain`（`practice_acts` 全真），可休息 / 普通出行 / 治病；**稽古成功仍按日常稽古结算
  Lv+1 / 槽清零（URA 不是合宿，不冻结）**。本番演出的训练限定效果只在 **72–77** 生效（见 §5.2），
  空窗期 68–71 不生效。
- 阶段机（内部强类型，对外 `StageId`）：S3 定为五阶段 `Begin(0) → Distribute(3) → Train(1) →
  AfterTrain(4) → End(2)`（**号只增不改**）；比赛 / 合宿 / 発表会 / 本番 / 空窗期 / URA 回合是**回合类型**
  （`TurnPlan`），不各开阶段；`Race / ActTrain / Outing` 是 `Train` 阶段里的动作，`CheckPoint` /
  合宿 +1 / 教诲分配都在 `End`。**担当分配是建局 / NPC 加入时的一次性动作，不是阶段**（见 §2.1）。

**回合结构（S3 已落地）**

- 阶段机（内部强类型 `Stage`，对外只投影 `StageId`）：一回合固定
  `Begin(0) → Distribute(3) → Train(1) → AfterTrain(4) → End(2)`；**号只增不改**。
- 回合类型 / 边界由 `TurnPlan`（每回合 `Begin` 派生一次）表达，**不各开阶段**：
  `race`（目标赛 / URA 决赛回合，分类不变）、`ura_race`（73/75/77）、
  `ura_period`（URA 回合 72–77）、`interlude`（剧本结束后的空窗期 68–71，由 `schedule` 末项 +1
  派生、至 URA 起点前）、
  `camp_year / camp_zone / camp_regular / camp_extended / camp_rest`、
  `camp_level_up`（15/39/63）、`check_point`（23/47/67 → 0/1/2）、
  `advice_window`（2/11/23/35/47/59）。
- **合宿窗口与延长算法**：从 `window.start` 开始本次合宿；每回合 `End` 计数，
  **目标赛 / 强制休息回合不计入**，计满**窗口长度（= 4）**才结束 → 顺延自动成立；
  `camp_rest` = 原窗口内 && 年次 ≥ 1（Junior 与延长段为普通休息）；
  **全演目 +1 仍固定日历时点 turn 15/39/63**（不随顺延推迟；`plan.camp_level_up` 供 S5 结算）。
- **马娘特殊事件（强制休息，临时口径）**：目标赛回合可被固定事件改为**实际执行休息**（退赛）——
  回合仍按 `plan.race = true` 分类，但**不产生比赛事件 / 奖励**，实际动作是休息；
  目前只登记凯斯奇迹 T65（键 = `chara_id = uma_id / 100`）。引擎当前没有「马娘特殊事件记录」
  数据结构（2026-11-04 确认），保留临时表；新增异常事件时手工补表。
- **结算时机统一在 `End`（用户 2026-11-01 确认）**：発表会 / 本番 buff 与一次性奖励、合宿全演目 +1，
  以及**教诲分配 / 调整（含 turn 23/47 的転成）全部在 `End`**；顺序是**先剧本结算、后教诲分配 / 调整**。
  turn 67（本番）是**正常回合**，本番结算在 `End` 阶段。
- **合宿回合**：5 个训练动作**全部变演目稽古**（不受 gauge 是否满影响）；这些稽古**不改变演目 Lv、
  不进演目槽**；Lv 只在该年固定结算点 +1。
- 比赛 / 演目稽古 / 出行是 `Train` 阶段的**动作**（S4 落），不为它们单开阶段。

## 2. 资源与账本

- 剧本资源：**5 条演目ゲージ**（对应 5 训练）+ **5 个演目 Lv**。
- **剧本机制自 turn 2 起**（2026-11-01 用户核对）：神驹加入 / 首次传授在 turn 2；**0–1 回合没有担当分配，
  训练 / 休息 / 出行 / 事件都不获取演目槽等剧本资源**。实现：`MatsuriGame::scenario_started`
  （turn ≥ [`SCENARIO_START_TURN`] = 2）在 `gain_act_gauge` / `gain_lowest_act_gauge` 入口拦截；担当分配
  数据仍是建局一次算定、不产生决策点（§2.1）。早期不入槽会位移冒烟（44946 → 40853 → 40899，S9 前不建基线）。
- gauge 上限 **5**（真机 `NeedActGauge = 5`）；不随回合自然减少。
- 入账（2026-10-31）：对应演目担当**每参与 1 人 +1**；**闪彩担当 +2**（同场其他仍 +1）；
  **目标比赛 +4**（按 4 次 +1 入账，落点与休息 / 外出同一三则：**演目 Lv 最低 → 槽最低 → 仍相同按 速→耐→力→毅力→智**，满槽跳过；并列逐次分摊）；
  休息 / 外出 / 非目标比赛 **+1**（落点同上三则）。
- 消费：gauge 满后对应训练变演目稽古；**成功**时该演目 `Lv +1`、gauge 清零；
  **失败 = 训练失败**：照常触发失败后事件、不给属性收益，且 **完全无效——槽不动、Lv 不升**
  （2026-11-01 修正，`shuntaisai_memo` 口径）。
- 可延期：亮起后不必立即执行、不会过期；多个演目同时亮起可任选其一，其他不消失。
  **所有亮起位置都会锁人**（见 §2.1）。
- **S5 已实现（2026-11-01）**：`game/mod.rs` `gain_lowest_act_gauge`（三则 + 满槽跳过）/ `gain_act_gauge`；
  训练入槽 `train.rs` `gain_training_gauge`；目标赛 / 休息 / 出行入槽在 `action.rs`；稽古成功
  `settle_training` 里 `add_act_level` + 槽清零（合宿不升不清）——gauge 入账 / 消费闭环已落。
- 跨回合状态存局面字段，不存阶段枚举。
- Senior 期各演目再 **+1 名担当**（memo；待真机）。
- 剧本链接角色（固定演目担当）按**固定演目**判定 gauge / 教え / 稽古登场，不按支援卡类型。
- 真机 `ActInfoArray` 每个元素：`ActType / ActGauge / Level / NeedActGauge / ActTrainingState /
  AdviceId / FriendOutingGainActLevel`；`ActType` 是主键（1–5），不是 `command_id`。

### 2.1 担当分配（一次性）与每回合人头分布（阶段）

> 2026-10-30 方案讨论拍板；实现时不要把两者混成一个阶段。

- **担当分配**是剧本开始建局时（含 turn 2 第一批 NPC 加入、turn 47 大成功第二批 +5）完成的**一次性动作**，
  **不是游戏阶段、不产生决策点、不占回合**；**turn 2 起生效**（0–1 回合无担当，见 §2）。五步流水线
  （link 钉位 → 卡按类型本位 → 整位 2 张卡容量 → 外派链 → NPC 每演目 1 人 → 吾妻余额）只在这里生效。
- **每训练位最多 2 张卡**只在担当分配时成立；进入训练人头分布后不受该限制，只受
  **每训练位最多 5 人（含 NPC）**约束。
- **每回合人头分布**才是阶段（`Distribute`）：
  - 普通训练：担当支援卡与 NPC 都按基础库算法（卡按类型 + 剧本得意率加成加权；NPC 无得意率、等权随机；
    均先判不在率）。
  - **任何槽满亮起的演目**：其担当卡与担当 NPC **必定出现并锁定在担当训练位**，**不判不在率**；
    **所有亮起位置都锁人**（不只当前要执行的那个）。只有**分身**和**未亮起位置**的担当可以跑到其他训练；
    因此亮起过多会减少其他位置的期望人头，**是否亮起 / 何时执行有策略性**（2026-10-31）。
  - 亮起位置不能做普通训练，只能选对应 `ActTrain`；多个亮起时所有亮起都可选。
  - 排练位上的非担当 NPC 仍可随机同框，但不计加槽人数、不推槽（§2.3）。
  - **理事长 / 记者（2026-11-05 用户实测修正）**：**不会出现在稽古训练位**——有稽古位时只落非稽古位；
    全稽古回合（合宿 / URA / 5 槽全满）**本回合完全不出现**。例：4 个稽古位 + 1 个普通位时，
    理事长 / 记者仍可能出现在那 1 个普通位。
  - **吾妻（2026-11-05 用户实测修正）**：**只要有稽古训练**，就必补到某个「未满 5 人」的稽古训练位
    （锁位后、其余人头前补位；**不判不在**、**不会出现在普通训练位**）；只有一个稽古位且未满 5 人时
    必定落在该位。无稽古的普通回合走通用不在判定与普通落位。
  - **每训练位至多 1 名「友人 / 团队 / 理事长 / 记者」**（通用规则，2026-11-05 用户补充）：口径同引擎
    `Person::is_friend()`（`train_type() > 4 || Yayoi || Reporter`）；同一位置已有这类人头时不再落入。
    引擎 `distribute_person` 自带校验，剧本侧自定义放位（理事长 / 记者 / 吾妻补位）同样校验。
- **`distribute` 整体重写**：不复用默认 `distribute_all` 的“全员同权随机”语义；`sample_bucket` /
  `absent_weight` 形态可复用。NPC 不在率先按 `absent_weight = 50`（约 9.1%）实现，待真机（U29）。
- **分身**：在 `distribution` 中以**同一人头下标重复占位**（不新建人头）；按占位逐个计数、不去重；
  唯一不生效的卡效果是友情（非本职训练位不亮彩圈）。详见 [`matsuri_memo_cn.md`](matsuri_memo_cn.md) §3.5。

### 2.2 人头的实现形态（S4 前置，已落）

- **剧本人头 `MatsuriPerson`** = 引擎通用 `BasePerson` + 剧本字段：`act`（担当演目）、`origin`
  （来源：卡 / 友人 / 编成外神驹 / 理事长 `Yayoi` / 记者）、`avail_turn`（可用回合）、`needs_great_success`
  （第 2 批神驹需 Classic 発表会大成功）。契约 `Person` 的 impl 整体在 `game/traits.rs`，
  `MatsuriPerson` 的构造 / 查询在 `game/person.rs`。
- **`PersonOrigin` 与 `PersonType` 分工**：`PersonType` 是引擎契约语义（缺省可用性 / 不在率 /
  分布顺序 / 红点 / 闪彩等，剧本不能扩展）；`PersonOrigin` 是剧本侧标签，构造时**单向决定**
  `PersonType`（Card→Card / Friend→ScenarioCard / Guest→Npc / Yayoi→Yayoi / Reporter→Reporter）。
  引擎只看 `PersonType`、剧本只看 `PersonOrigin`，互不反推。
- **名单布局**：卡组人头（`persons` 前缀与 `deck` 同序，含友人卡）→ 理事长 → 记者 → 编成外神驹
  「第 1 批 5 名固定 + 带吾妻余额 1」→「第 2 批 5 名」。**两批神驹规则上同质**（`PersonOrigin::Guest`），
  只靠 `avail_turn`（2 / 48）与 `needs_great_success` 区分；**理事长 T1 起出现（2026-11-04 真机修正，T0 不出现）、记者 T13 起**，其余按引擎基础局默认处理。
- **担当 ≠ 站位**：`act` 是建局一次性分配结果（link 钉位 → 卡按类型本位 → 外派链 → NPC 每演目 1 人 →
  余额），不随回合变；每回合站位（`distribution`）在 `distribute.rs`。得意率每次按卡面
  `calc_training_effect` + 剧本加成现算，不回写 `deck.effect`（2026-11-04 确认）。
- **同 `chara_id` 约束（模拟口径）**：不允许两个不同人头同 `chara_id`（同 chara 只能以
  `distribution` 重复占位的形式作分身）。编成卡 / 育成马娘 / 5 名 link 角色 / 已出现人头都会
  从「随机非 link 角色」候选中排除；**育成马娘本身是 link 角色时，该演目固定神驹换成随机非 link 顶替**。
- **随机非 link 角色取人（离线简化）**：真机从马娘池随机抓；本模拟从 `chara_id` 1001 起按序取
  第一个满足条件者（见 `stubs.md` 登记，接在线模式时可换成随机）。

### 2.3 编成检测（S4 前置，已落）

担当机制对编成敏感，建局前统一检查（`game/deck.rs` `inspect_deck`；宿主可先用它自查）。
**禁止项**拒绝建局（`newgame` 返回 `Err`）；**警告项**不阻止建局，随 `MatsuriGame::deck_warnings`
/ `MatsuriView.deck_warnings` 下发（CLI 在跑局前打印）。

| 类 | 项 | 内容 |
|---|---|---|
| 禁止 | E1 | 没带 SSR 吾妻 |
| 禁止 | E2 | 友人卡多于 1 张 |
| 禁止 | E3 | 带 SSR 吾妻以外的友人卡（含 R 吾妻） |
| 禁止 | E4 | 卡组不符合通用规则：**必须 6 张**（5 普通支援卡 + 1 友人）/ 无重复人物 / 不含担当马娘 / 卡类型正确（**含团队卡拒绝**） |
| 警告 | W1 | 剧本 link 卡类型与其固定演目不一致（如速重炮被钉在力量演目；**link=固定演目本身是合理情况**） |
| 警告 | W2 | 同一类型卡 ≥ 3 张（整位容量 2 张，必然外派） |
| 警告 | W3 | 卡被外派到非本职演目（担当位置溢出到别的训练；同类 <3 张时也可能发生，故与 W2 分开） |
| 警告 | W4 | 编成支援卡类型 < 5 种（含友人；演目 Lv 效果的「5 种卡」列无法发动） |

  link 角色导致的神驹顶替（合理情况）；link 卡类型与固定演目一致（零增量）。
- **剧本友人（吾妻）也是剧本 link 角色，但不参与 roster / 担当分配**；W4 的「类型种数」按
  含友人计（与 `condition_value = 5` 的「含友人」口径一致），W1 只对参与担当的支援卡判定。
- 检测报告同时返回卡侧担当分配结果，`roster` 直接复用（避免重复计算）。

  （`memo` 2026-10-31，已入资产 `training.normal`）。

- **训练Lv 口径（2026-11-03 核对）**：每种普通训练**成功**执行 4 次 → 该训练位基础 Lv +1
  （`train_level = floor(成功次数 / 4) + 1`，等价 `count/4+1`）；**発表会大成功的一次性 +1**
  （第 1 / 第 2 回各 +1）记独立 `train_level_bonus`，**与计数等级相加**后夹剧本资产上限 **5**；
  **演目稽古（含合宿排练）不计基础训练计数**，训练失败也不计数（引擎基础局同型）。面板 / View 的
  `board.train_levels` 即此最终等级；公式落点 `traits.rs::train_level`，计数落点 `train.rs::settle_training`。

**计算公式（`memo` 2026-10-31，主 / 副属性拆分，上段）**

- **主属性**：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计) × (1 + 主获得量合计)) - 下段`。
- **副属性**：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + 副获得量合计)) - 下段`；
  **副获得量与训练效果同层加算**（不是再乘一层；`memo` 2026-10-31）。
- SP：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + SP训练效果)) - 下段`。
- **演目稽古：全五维基础各 +10**（act_lv `all_status_bonus`，Lv1–10 恒 10）——**2026-11-01 拍板：
  加在上层乘区之后（flat，不受乘区 / 上昇量上限影响）**；未使用维也 +10。
- 下段 = 通常通り：普通训练取该训练位 / 该训练 Lv 的基础值；稽古取当期档（§3.2）。
- 友情合计（仅友情训练）：駿大祭 buff、協力教え、稽古的演目 Lv 效果、得意率転成（稽古）。
- 训练效果合计：助力（非友情时）、助力支撑、両道（稽古）、不屈（稽古）。
- 主获得量合计：特化、絆（稽古）、絆転成（稽古）。
- 副获得量合计：両道（SP 除外；与训练效果同层加算）。
- 教え效果按「教え绑定的演目担当**参与人数**」叠加；**効果等级 = 所绑定演目的 Lv（1–10）**，与训练种类无关；
  **改派后随新演目的 Lv 改变**。例外：**絆 +3 为平摊、不按人数叠加**（见下）。
- **两层口径（2026-10-31）**：**下层直接用基础库原始公式（`default_calc_training_value`）**算普通训练值；
  卡面 / 通用项（友情、训练效果、人数、干劲、成长率等）都在下层。**剧本加成相关的数值全部体现在上层**：
  演目 Lv 效果、教え、発表会 buff、稽古 +10 等按上面的“友情合计 / 训练效果合计 / 获得量合计”叠加，
  **不重复计入下层已有项**。每个剧本 buff 的乘区归属按规则表落实现；两层结构已定，具体数值细节仍可复核。
- **上层实现（S5）**：`game/train.rs` `training_upper` 用剧本侧合计按上式算主 / 副 / SP 增量，
  再按**上昇量上限**封顶；**上限 = 规则 100 + 特化教え `status_limit`（按参与担当聚合）+
  稽古且 5 种卡时该演目 Lv9/10 的 `status_limit`；SP 上限同法并叠加 `sp_limit`**（2026-11-01 拍板；
  属性基础上限 2200 组是否同步上抬未确认，见 `stubs.md`）。
  体力：稽古按体力教え / 転成 `keiko_vital_cost_drop` 百分比降耗；URA 训练（**仅 72–77**）再 +30 体 /
  +1 干劲（本番演出；空窗期 68–71 不生效）。体力先结算稽古耗体 / 训练扣体 / 失败率下降，再叠加 +30 回体，
  因此 URA 训练常为**净回体**。
- **取整（2026-10-30）**：所有乘算收益（比赛加成、剧本倍率等）统一 **floor**，不用 round；
  目标赛 SP `72 × 1.3 = 93.6 → 93` 已按此口径。
- **演目稽古基础值按时期两档**（Junior / Classic 及以后；见 §3.2 注）；**无 Senior 第三档**
  （第二档覆盖 Classic 与 Senior，U02 2026-11-01 收口）；**基础值没有 Lv2–10 维度**（`command_level` 只查
  演目效果 / UI；mdb 5101–5105 只有 Lv1 一组行；「稽古 +10」来自 `act_effect 105`，Lv1–10 恒 10）。

### 3.3 教え（教え）加成

- 教え作用于「演目担当」（含编成外神駒），不是全体人头；羁绊教え只对编成支援卡生效。
- 效果按「教え绑定的演目担当参与人数」叠加（例：助力担当 2 人则助力效果 2 倍）；
  演目 Lv 取**教え绑定的演目**，与训练种类无关。**絆の教え例外：+3 平摊、不按人数叠加**，
  作用于全编组卡并与训练本身的绊上升合算（参加友人 +7 / 参加非友人 +10 / 不参加 +3；愛嬌合计再 +2）。
- 転成效果同样按参与担当人数叠加。
- **助力支撑获得口径（2026-11-02 用户确认）**：成功演目稽古的训练位参与占位中含「助力绑定演目担当」即可
  获得 / 重置为 3，**不要求必须是该演目自己的稽古**（参与者口径，与教え通用规则一致），不收窄。
- 实现口径（memo 调查项）：特化的基础上限也作用于 SP 上限；稽古 +10 不吃非得意加成；
  转成的「灵感 +1」= Hint Lv+1；**Lv4+ 全灵感发动不含嘉宾**；
  研鑽发生率**1 回合 1 次共通掷骰、`p = r(绑定演目Lv)`、不按担当人数加算**（`memo` 2026-10-31，推翻旧口径），
  掷中则所有该演目担当参与的成功训练都触发，仅成功时结算。
- **S5 实现口径（2026-11-01）**：`game/advice.rs` `advice_slot_effect` 按「新教诲效果（绑定演目 Lv）+
  被消耗基础教诲的固定転成升级效果」聚合；`participant_advice` 遍历训练位占位按参与担当人数叠加
  （絆 +3 取 max 平摊）；助力支撑 = 3 次内训练效果 +5%（`rules.assist_support`，再次获得重置）；
  研鑽追加稽古在 `Begin` 用策略流预掷、训练成功且绑定演目担当参与时按 50/50 上 / 下档结算
  （上档：直前训练属性 +20 / SP +20 / 最低演目槽 +1 / 理事长羁绊 +5 / 体力 -5 / 简化解一个 debuff；
  下档：属性 +5 / 体力 +5）。教诲 5 槽永远满、效果随改派即时换级。
- 逐级数值见 [`plan/intake.md`](plan/intake.md) §3.4；下表只记口径：

| 教え | 作用 | 关键口径 |

### 3.4 其他

  `rules.friendship_gain`（友人 +4 / 普通卡 +7 / 理事长·记者 +5；絆教え参与时全编组卡再 +3 平摊；
  愛嬌由 `add_friendship` 统一 +2 一次）；编成外神驹只计人头、不给羁绊；灵感事件走剧本公式

### 6.2 手写训练员（S7，2026-11-02）

**目标口径（pt_favor）**

- 单位统一为评分点：`官方评分 = Σ 五维公式分（umaai_core::score::status_point，按本局上限夹取）+ PT × pt_score_rate`；
  训练员再对 PT 施加 `pt_favor_rate`（`1.0` = 官方评分，默认 `2.0` 沿用引擎既有定档）；
  动作 / 事件 / 教诲分配全部折算到同一量纲，不加第二评分轴。
- 公式以原始属性为输入、没有属性上限；`data/constants.json` 已删除 `five_status_final_score`
  表（该表在引擎侧仅为旧数据兼容保留），本仓数据资产不再带这份查表数据。
- 五维边际 = `公式(夹取后 after) − 公式(夹取后 before)`；超过本局上限后边际为 0。

**动作决策（`Trainer::select_action`）**

1. 候选只有 1 个 → 直接选（强制比赛 / 强制休息回合）。
2. 候选全是教诲分配方案 → 价值矩阵择优（见下）。
3. 生病 / 不擅长且可选治病 → 治病（变胖只影响训练速度、每回合 20% 自解，不占动作）。
4. 其余候选统一打分，取最高（确定性；同分取先出现者）：
   - 训练 / 稽古：`成功收益 × (1−失败率) + 失败惩罚 × 失败率`；成功收益 = 官方评分边际（属性 + PT）
     + 体力 / 干劲 / 羁绊 / 灵感估值 + 演目槽 / Lv / 発表会达标急迫 + 亮起囤积惩罚 + 追加稽古掷中兑现；
   - 休息：普通档按 `rest_probs` 期望体力 + 演目槽 +1；合宿版 +40 体 / +1 干劲；低于 `rest_vital` 再加权；
   - 普通出行 / 友人出行：出行事件期望值 + 演目槽 / Lv 资源；`friend_outing_early` 时友人出行加分；
   - 比赛：强制回合给保底；自选比赛由 `self_race` 开关控制（默认关），开时按等级事件期望 × 比赛加成估算；
     `freeRaces` 义务区间另加紧迫度软加分与硬保底（§6.5）；
   - 治疗：生病 / 不擅长时给保底，否则 0。
5. 策略旋钮全部来自 `MatsuriConfig [trainer]`（见 `data/matsuri_config.toml`）；`value.rs` 内的公式常数
   （失败惩罚 / 闪彩分 / 追加稽古兑现分等）为内部参数，不散落魔法数。

**溢出与末段稽古（2026-11-03 新增）**

- **溢出层 `[trainer.overflow]`**：按**生效上限** `five_status_limit` 判定近顶
  （`margin` = 剩余空间比例阈值）；非近顶轴权重 `× (1 + tilt × 近顶轴数 / 5)`；
  主属性近顶时，副属性 + PT 另给 `keep` 保留加分，避免「速训练 → 力量 / PT」被完全倾斜。
  只作用于训练估值，事件 / 比赛 / 教诲分配不套用。
- **末段稽古 `[trainer.endgame]`**：窗口 = 第三年合宿结束后～T71；只在普通回合生效
  （非合宿 / 非 URA / 非比赛 / 非强制休息）。`pending` = 满槽演目数，`normal_turns` =
  窗口内剩余普通回合数，`pressure = max(0, (pending − normal_turns) / pending)`。
  满槽 `ActTrain` 加 `keiko × (1 + scarcity × pressure)`，未满 `act Lv` 加
  `level × min(gap, 2)`；普通 `Train` 扣 `normal_penalty × pressure`。URA 72–77 不进入本窗口。
- **默认档**：`margin 0.02 / tilt 0.5 / keep 0.15`；`keiko 250 / scarcity 1.0 / level 80 /
  normal_penalty 120`。100 seed discovery（61444–61543）上 106301 +245（t=3.24），
  但 200 seed holdout（61544–61743）未复现（三马 −33 / +7 / −7，|t|<1.2），
  判定为**行为控制旋钮**；基准 seed 61444 的冒烟逐位不变。

**事件决策（`select_event_choice`）**

- 组内结果行按 `prob` 加权求期望：`ActionValue`（属性 / PT / 体力 / 干劲 / 羁绊 / 灵感）
  + `ExtraStatus`（随机 N 项按当前五维平均边际、`last_train` 按上次训练轴）+ 状态增删（变胖等）+ 友人卡加成；
- 追加稽古 `400015106` 上档额外计入「最低演目槽 +1」与「解一个 debuff」的价值；
- 17 个 `player_select` 决策点全走同一打分，不再恒取首项。

**教诲分配决策（`decide_advice_assignment`）**

- 决策点：T2 `Begin`（授予后）+ turn 11/23/35/47/59 的 `End`（23/47 先应用配置融合再分配）；
- 每窗口把 120 个排列一次性作为 `Action::AssignAdvice` 候选交 `Trainer::select_action`（合并方案，
  不拆 5 步）；选择确定性、不耗决策随机流（回放 / CRN 可复现）；
- 价值矩阵：对每个候选逐演目求 `槽效果 × 演目上下文`（预计训练 / 稽古次数、担当数、卡数、平均羁绊、
  非友情概率、演目 Lv、発表会达标急迫、合宿窗口、追加稽古发生率、不屈可靠性等），`Σ` 为方案分；
  与 `apply_assignment` 的 `801` 硬约束同口径（估值前先把 801 槽折到担当数最多演目）；
- **融合仍走配置预设**：`settle_advice_window` 内 `fusion_plan(window)` 是唯一入口，将来若要交 Trainer
  （按配置固定选），只改该函数、不动决策协议。

**随机轴纪律**

- 手写训练员全决策为确定性，**不消耗决策随机流**；同种子两次跑局逐位一致
  （`handwritten_trainer_is_deterministic`）。

### 6.4 幸运体质（生病盾，2026-11-06 合并）

### 6.5 自选比赛义务区间（freeRaces，2026-11-06 接线）

- **数据语义**（`umaDB.json` `freeRaces`）：`startTurn`/`endTurn` 区间、`count` 需打场数、可选 `grade`
  等级门槛；**只有部分马娘有**（当前数据 116/272）。区间掩码由引擎载入时按比赛等级表算好
  （`update_turn_mask`）：**只放行不低于门槛的比赛**——`grade=1` 只放 G1（`*grade <= g`，1=G1 最高），
  `grade=3` 放 G1–G3，更低的 G4/OP 被挡。区间外 / 无 `freeRaces` 的马娘没有义务。
- **判定时机（2026-11-04 真机修正）**：在**区间最后一回合的 `End`** 判定（`settle.rs::settle_free_race_deadline`），
  不再等到下一回合开始；未达标 → `career_failed = true`、diag「【自选比赛】…育成失败（终止）」、
  `next()` 返回 `false` 直接终止；`on_simulation_end` 检测失败标记并**跳过育成终了奖励**
  （真机口径「育成终止并结算当前评分」）。
- **达标奖励**：区间达标即触发**一次「生涯比赛胜利」事件**（`system_events.race_career`，面板值 5/72）：
  五维与 PT 吃 `race_scale`（卡面赛后 × 剧本赛后）与 `race_pt_rate`（铁心等），在**同一回合的 `End`**
  结算（`stage.rs` End 阶段排空 `unresolved_events`）；每个区间一次，不改变 `freeRaces` 场数统计。
- **可用性**：通用额外自由赛逻辑不变（`self_race` 开关 + `can_self_race()`：turn 13–71 且等级表非 0）；
  义务区间不额外限制「只能在这里打」，区间外的额外赛也不计入义务场数。
- **训练员**：
  - 紧迫度 `urgency = need / left`（`free_race_progress()` = 当前区间剩余需打场数 / 掩码内剩余可赛回合数，
    封顶 1.0）；`race_value += [trainer].free_race_urgency × urgency × FORCED_RACE_BASE(500)`；
  - **硬保底**：`need ≥ left`（再不打赢不了）→ 守门⓪ 直接选「比赛」，优先于治病 / 合宿 / 友人截止 /
    体力危险 / 心情崩坏等其它守门，且**不受 `self_race=false` 限制**（义务补足与「额外多打」分开）；
  - `self_race=false` 时纯额外自由赛仍不参与比较（`race_value = −∞`）。
- **验收数字**：100101（无 `freeRaces`）100 局**逐位不变**（均 73155.0）；
  102102 玉藻（12–28 需 1 场 + 29–48 需 4 场且 ≤G3）100 局 74051.7 → **70876.0（−3175.7）**、
  ≥LG 30 → 2、**无育成失败**（每局补 5 场义务赛）；seed 62100 冒烟 75460 / US9 → **64686 / US1**。
  有义务马娘评分下降属预期（回合用于比赛而非训练）。
  **2026-11-04 更新（新因子 + 继承 + 本修正后）**：100101 均 **78124.5**（PT 11052.2）；
  102102 均 **76406.6**（≥LG 57、PT 10979.2、`career_failed` 0；每局 T28 / T48 各入账一次
  「生涯比赛胜利」奖励），seed 61444 冒烟 **76002**。
- ❓`race_grades` 标准表与真机自由赛格子分布的对齐（尤其 G1/G2 格子）待真机复核；该表同时决定
  区间掩码与可达性。

### 6.6 搜索训练员（FlatSearch 集成层，2026-11-04）

- **形态**：`MatsuriSearchTrainer` 包一层 `FlatSearch<MatsuriGame>`（引擎现成内核：均匀 / UCB
  分配、CRN 配对种子、并行 rollout），手写 `MatsuriTrainer` 作 fallback 与 rollout 基策；
  **rollout 基策不带搜索**，防递归。
- **预算**：`matsuri_config [search].search_n` = **每个候选**的 rollout 次数（引擎口径）；
  `0` = 手写档。单局验证 1024 / 2048，生产目标 8192；一个决策点总量 = 候选数 × `search_n`
  （UCB 开时是每候选预算上限，实际按 UCB 动态分配）。
- **三类作用面**（`[search] train` / `advice` / `event`）：
  - `train`：全部 `Train` 候选直接 `FlatSearch::search`（ramen 口径，不剪枝）；
  - `advice`：120 排列先按手写价值矩阵剪到 top-16，再对子集搜索，结果映射回原下标；
  - `event`：事件不是 `Action`，用 dummy action token 走 `FlatSearch::search_with`，闭包内
    应用当前选项后，从 `event_queue` 的下一个事件继续（`event_cursor` 留在局面上），
    再跑后续 stage 到终局。
- **搜索口径**：`MatsuriGame::search_score(pt_favor_rate)` = 技能 + PT×`pt_score_rate`×`pt_favor_rate`
  + 五维公式；`pt_favor_rate` 取 `[trainer].pt_favor_rate`，与手写剪枝同一目标函数。
  失败分支（`career_failed`）按实际 `calc_score`，不加额外罚。
- **排序与激进度**：中选下标用 `weighted_mean(radical_factor)`（`rank_ratio^rf` 加权）。
  `radical_factor_max = 0.0` 即普通均值；越大越偏高尾。理想测试（106301 + 小切 + 心情盾×2，
  seed 61444）Train-only 1024：`radical=1.0` 84209、`radical=0.0` **86711 / LG17**；
  Train-only 4096 `radical=0.0` **86955 / LG17**。普通马娘 100101（同 pre、Train-only、
  `radical=0.0`）：手写 82807 / LG10 → 1024 **85095 / LG14** → 4096 **85184 / LG14**；
  比狄杜斯多涨约 800 分，符合「铁心后五维接近上限、面板分边际小」的预期。当前仓默认引擎值
  50 只作内核缺省，搜索档实跑前应显式设为 0.0 或扫参；`expected_search_stdev` 只进 UCB
  探索项，不改排序。
- **随机流**：与 ramen 一致，`FlatSearch` 每次恰好从调用方决策流取一个 `next_u64`
  派生 rollout 种子；局面规则流由 `fork_for_rollout(seed)` 按 `(seed, 回合)` 独立派生，
  搜索不读 / 不改真实局面的规则流。`search_consumes_one_decision_draw` 守门。
- **日志**：搜索 interval 由 `DiagGuard` 静默，结束后每个决策点一行 `【搜索】` 摘要
  （候选数 / `search_n` / 中选 / 加权均值 / 耗时）。
- **叶子估值器**：`LeafEvaluator` trait + `ScoreLeaf` 占位已预留；引擎当前没有截断 leaf hook，
  `max_depth > 0` 在构造搜索训练员时直接报错；生产 `max_depth = 0`（跑到终局）。
- **单局验证**（seed 61444，默认档）：手写 81553 / LG8、PT 11490；1024 档 83326 / LG11、
  PT 11602、90.8 s；2048 档 83519 / LG11、PT 11901、180 s。单局冒烟，不是基线；
  同种子两次逐位一致由 `tests/search.rs` 守门。
- **已知口径**：事件搜索应用当前选项后从下一事件继续；同一 stage 内的事件顺序与主路径
  一致，但搜索分支的后续事件由手写基策选择（不是逐事件再展开）。

## 7. 随机轴与可复现

- 局面流 / 事件流：由 `BaseGame` 持有，每回合按 `(master, turn)` 派生。
- 策略流：本局面自持，动作结算与剧本机制随机从它取；`set_rule_master` 与回合边界重置。
  S5 里**追加稽古预掷**（`Begin`）与训练结算走策略流；**每回合人头分布 / 灵感分配**走回合固定流
  （`streams.turn_fixed`，与引擎基础局 `distribute_all` 同轴）。
- 决策流：只给 `Trainer`，不影响结算随机。
- `fork_for_rollout`：克隆 + 注入 rollout 主种子；任何不由传入 rng 驱动的流必须在这里重置。
