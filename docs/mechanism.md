## 1. 回合与阶段

> 口径：本文 turn 一律 **0 基**（`turn ∈ [0, 77]`）；`master.mdb` / 游戏内显示为 1 基，必要时在括号内保留原始值。

- 回合范围：`turn ∈ [0, 77]`（全 78 回合）；Senior 10 月後半最终结算在 `turn 67`。
- 三次剧本结算 / 進捗発表会：`turn 23 / 47 / 67`，门槛全演目 Lv `3 / 5 / 6`
  （`single_mode_15_schedule`；`need_act_num = 5`）。
- 合宿窗口：`turn 12–15 / 36–39 / 60–63`（0 基；Junior 即有夏合宿）。
- **合宿规则**（官方帮助）：合宿中**每回合都能进行演目稽古**；合宿中**演目 Lv 不上升**；
  合宿结束后**全演目 Lv +1**；合宿中无体力回复事件（「不回体」仅指没有合宿内回体事件）。
- **合宿延长**（user 实测 2026-10-26）：基础 4 回合；若合宿窗口内出现目标比赛或强制休息，
  合宿按回合顺延，直到该年累计 **4 个非比赛合宿回合**。比赛回合与强制休息回合不计入这 4 个。
  - 例：樱花进王顺延到 10 月前半（0 基 turn 66）；凯斯奇迹 9 月前半比赛、9 月后半比赛触发强制休息，
    10 月前半仍有顺延合宿回合。
  - 合宿结束全演目 Lv +1 的结算点**固定为该年 8 月后半结束（turn 15 / 39 / 63 结束时）**，
    不随顺延推迟。
  - **延长回合属性（U18，2026-10-31）**：**所有年份的延长回合都算合宿（全部为排练）**；
    第 1 年的延长回合也按第 1 年合宿规则（正常休息 / 可外出 / 可有支援卡事件）。
- **合宿外出 / 休息（U33，2026-10-31）**：**第 2/3 年合宿不能普通 / 友人外出，休息为合宿版**；
  **第 1 年正常休息，可普通 / 友人外出，可有支援卡事件**。
- **合宿期事件**（user 2026-10-30）：**第 1 年**合宿支援卡连续事件 + 普通马娘事件都发生；
  **第 2/3 年**常规合宿回合两类都不发生；**延长段的个体固定事件仍发生**；
  延长段是否触发支援卡连续事件待测（U19）。**抑制表 / 不可发生连续事件回合表由剧本自持重做，
  不复用引擎 `no_event_turns`**（见 §5.3）。
- 本番后：剧情结束，但仍可攒 gauge / 执行演目稽古直到 `turn 77`（URA 收尾）。
- 阶段机（内部强类型，对外 `StageId`）：当前 S1 阶段机为 `Begin → Train → End`；真实阶段至少含
  **`Distribute`（每回合人头分布）**，并按合宿 / 伝受 / 発表会 / 本番 / URA 收尾拆分。
  **担当分配是建局 / NPC 加入时的一次性动作，不是阶段**（见 §2.1）。❓精确阶段顺序待收口。

## 2. 资源与账本

- 剧本资源：**5 条演目ゲージ**（对应 5 训练）+ **5 个演目 Lv**。
- gauge 上限 **5**（真机 `NeedActGauge = 5`）；不随回合自然减少。
- 入账（2026-10-31）：对应演目担当**每参与 1 人 +1**；**闪彩担当 +2**（同场其他仍 +1）；
  **目标比赛 +4**（按 4 次 +1 入账，落点按**演目 Lv 低→高**，同级按 速→耐→力→毅力→智 顺序，满槽跳过）；
  休息 / 外出 / 非目标比赛 **+1**（落点 Lv 最低→槽最低→属性序）。
- 消费：gauge 满后对应训练变演目稽古；执行后该演目 `Lv +1`、gauge 清零；
  **排练失败 = 训练失败**：照常触发失败后事件、不给属性收益，但 **演目 Lv 仍 +1**；
  **槽清零**（已确认）。
- 可延期：亮起后不必立即执行、不会过期；多个演目同时亮起可任选其一，其他不消失。
  **所有亮起位置都会锁人**（见 §2.1）。
- 跨回合状态存局面字段，不存阶段枚举。
- Senior 期各演目再 **+1 名担当**（memo；待真机）。
- 剧本链接角色（固定演目担当）按**固定演目**判定 gauge / 教え / 稽古登场，不按支援卡类型。
- 真机 `ActInfoArray` 每个元素：`ActType / ActGauge / Level / NeedActGauge / ActTrainingState /
  AdviceId / FriendOutingGainActLevel`；`ActType` 是主键（1–5），不是 `command_id`。

### 2.1 担当分配（一次性）与每回合人头分布（阶段）

> 2026-10-30 方案讨论拍板；实现时不要把两者混成一个阶段。

- **担当分配**是剧本开始建局时（含 turn 2 第一批 NPC 加入、turn 47 大成功第二批 +5）完成的**一次性动作**，
  **不是游戏阶段、不产生决策点、不占回合**。五步流水线（link 钉位 → 卡按类型本位 → 整位 2 张卡容量 →
  外派链 → NPC 每演目 1 人 → 吾妻余额）只在这里生效。
- **每训练位最多 2 张卡**只在担当分配时成立；进入训练人头分布后不受该限制，只受
  **每训练位最多 5 人（含 NPC）**约束。
- **每回合人头分布**才是阶段（`Distribute`）：
  - 普通训练：担当支援卡与 NPC 都按基础库算法（卡按类型 + 剧本得意率加成加权；NPC 无得意率、等权随机；
    均先判不在率）。
  - **任何槽满亮起的演目**：其担当卡与担当 NPC **必定出现并锁定在担当训练位**，**不判不在率**；
    **所有亮起位置都锁人**（不只当前要执行的那个）。只有**分身**和**未亮起位置**的担当可以跑到其他训练；
    因此亮起过多会减少其他位置的期望人头，**是否亮起 / 何时执行有策略性**（2026-10-31）。
  - 亮起位置不能做普通训练，只能选对应 `ActTrain`；多个亮起时所有亮起都可选。
  - 排练位上的非担当 NPC 仍可随机同框，但不计加槽人数、不推槽（§2.3）。
- **`distribute` 整体重写**：不复用默认 `distribute_all` 的“全员同权随机”语义；`sample_bucket` /
  `absent_weight` 形态可复用。NPC 不在率先按 `absent_weight = 50`（约 9.1%）实现，待真机（U29）。
- **分身**：在 `distribution` 中以**同一人头下标重复占位**（不新建人头）；按占位逐个计数、不去重；
  唯一不生效的卡效果是友情（非本职训练位不亮彩圈）。详见 [`matsuri_memo_cn.md`](matsuri_memo_cn.md) §3.5。

## 3. 训练与加成

### 3.1 命令与基础值

- 普通训练命令：`101` 速度 / `105` 耐力 / `102` 力量 / `103` 根性 / `106` 智力（`104` 未在本剧本使用）。
- 演目稽古命令：`5101`–`5105`，`base_command_id` 分别映射上述普通命令；
  `command_level = 演目 Lv`（1–10）。
- **演目稽古是独立动作 `ActTrain(act)`**，不是普通 `Train(slot)` 的变体；与普通训练并列进入动作集。
  执行后该演目 `Lv +1`、该槽清零；**失败 = 训练失败（触发失败事件），但 Lv 仍 +1**；
  执行稽古的回合 5 个演目槽都不涨（按行动算）。
- 基础值（`single_mode_training_effect`，`result_state = 2`）：

| command | 速度 | 耐力 | 力量 | 根性 | 智力 | SP | 体力 |
|---|---|---|---|---|---|---|---|
| 101 速度 | 12 | 0 | 2 | 0 | 0 | 7 | -20 |
| 105 耐力 | 0 | 10 | 0 | 3 | 0 | 7 | -20 |
| 102 力量 | 0 | 6 | 9 | 0 | 0 | 7 | -21 |
| 103 根性 | 2 | 0 | 2 | 12 | 0 | 7 | -21 |
| 106 智力 | 2 | 0 | 0 | 0 | 8 | 6 | +5 |
| 5101 流鏑馬 | 16 | 0 | 3 | 0 | 0 | 9 | -25 |
| 5102 神旗争奪戦 | 0 | 14 | 0 | 6 | 0 | 10 | -25 |
| 5103 納舞 | 0 | 6 | 14 | 0 | 0 | 10 | -25 |
| 5104 大曳神輿 | 3 | 0 | 2 | 15 | 0 | 10 | -25 |
| 5105 飛駆 | 3 | 0 | 0 | 0 | 12 | 8 | -25 |

**计算公式（memo 2026-10-27，上段）**

- 基础能力：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计) × (1 + 获得量合计)) - 下段`；
  **演目稽古再 +10**。
- SP：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + SP训练效果)) - 下段`。
- 友情合计（仅友情训练）：駿大祭 buff、協力教え、稽古的演目 Lv 效果、得意率転成（稽古）。
- 训练效果合计：助力（非友情时）、助力支撑、両道（稽古）、不屈（稽古）。
- 获得量合计：主属性：特化、絆（稽古）、絆転成（稽古）；副属性：両道（SP 除外）。
- 教え效果按「教え绑定的演目担当**参与人数**」叠加；演目 Lv 取绑定演目，与训练种类无关；
  **絆 +3 也按人数 +3×N（全编组卡，未在场的卡也算）**。
- **两层口径（2026-10-31）**：**下层直接用基础库原始公式（`default_calc_training_value`）**算普通训练值；
  卡面 / 通用项（友情、训练效果、人数、干劲、成长率等）都在下层。**剧本加成相关的数值全部体现在上层**：
  演目 Lv 效果、教え、発表会 buff、稽古 +10 等按上面的“友情合计 / 训练效果合计 / 获得量合计”叠加，
  **不重复计入下层已有项**。每个剧本 buff 的乘区归属按规则表落实现；两层结构已定，具体数值细节仍可复核。
- **取整（2026-10-30）**：所有乘算收益（比赛加成、剧本倍率等）统一 **floor**，不用 round；
  目标赛 SP `72 × 1.3 = 93.6 → 93` 已按此口径。
- **演目稽古基础值按时期两档**（Junior / Classic 以后；见 §3.2 注）；**Senior 第三档暂定没有**
  （未完全确定，U02）。

### 3.3 教え（教え）加成

- 教え作用于「演目担当」（含编成外神駒），不是全体人头；羁绊教え只对编成支援卡生效。
- 效果按「教え绑定的演目担当参与人数」叠加（例：助力担当 2 人则助力效果 2 倍）；
  演目 Lv 取**教え绑定的演目**，与训练种类无关；**絆 +3 同样 +3×N（全编组卡）**。
- 転成效果同样按参与担当人数叠加。
- 实现口径（memo 调查项）：特化的基础上限也作用于 SP 上限；稽古 +10 不吃非得意加成；
  絆 +3 吃愛嬌補正且单独加算；転成的「灵感 +1」= Hint Lv+1；**Lv4+ 全灵感发动不含嘉宾**；
  研鑽发生率按担当人数加算、上限 100%、仅成功时触发。
- 逐级数值见 [`plan/intake.md`](plan/intake.md) §3.4；下表只记口径：

| 教え | 作用 | 关键口径 |
|---|---|---|
| 絆の教え | 絆 +3×N（按参与担当人数叠加，全编组卡）+ 演目稽古主基础 % | `effect_type 16 / 13` |
| 得意率の教え | 得意率 +10…50 | `effect_type 4` |
| ヒントの教え | 灵感率 +30…80% | `effect_type 2` |
| 助力の教え | 非友情训练效果 +20…40% + 「助力の支え」 | `condition_type 3` |
| 体力の教え | 演目稽古体力消耗 -1…15% | `effect_type 3`（负值） |
| 特化の教え | 主基础 +5…25% + 基础上限 +5…25 | `13 / 206` |
| 研鑽の教え | 「追加の稽古」发生率 20…80% | `effect_type 8` |
| 協力の教え | 友情 +1…10% + 该演目每个担当（卡+NPC）各额外 1 处（仅第三年 401+801 后出现） | `202 / 18` |
| 不屈の教え | 体力阈值下失败率 -100%；Lv8+ 追加演目稽古效果 | `205（cond 2）/ 203` |
| 両道の教え | 副基础 +1…25% + 演目稽古效果 +1…15% | `21 / 203` |

## 4. 比赛与赛程

- 赛程：各马娘固有目标赛事 + URA 决赛收尾；Senior 10 月後半本番为剧本最终结算，不是育成结束。
- 合宿期间有目标比赛则合宿延长：**不产生额外回合**，把后续正常回合改标为合宿回合；
  规则是**每年保证 4 个非比赛合宿回合**，比赛 / 强制休息回合不计入，按回合顺延。
- 合宿产出实测约 **2.59×** 普通回合（964 份报文：普通 n=63 中位 +56 / 合宿 n=12 中位 +145）；
  这是合宿整体产出比（含休息与稽古），**不能当纯稽古倍率**。❓用途待定（训练员估值）。
- 延长段的支援卡事件见 §1 / §5.3；演目 Lv +1 结算点已定（§1）。
- **赛后奖励（2026-10-30 定稿，剧本专属奖励表）**：目标赛 五维 +5、SP +72；目标外 GI 随机 1 项 +10、SP +45；
  目标外 GIII 随机 1 项 +8、SP +35；URA 预选 / 准决赛 / 决赛 五维 +10、SP +40 / 60 / 80。
  比赛加成对**五维与 SP 都乘算**，统一 **floor**；❓目标外「1 项」是否随机待测。
- 属性上限：**2200 / 1850 / 1800 / 1700 / 1800**（official + memo 一致），上限突破后 2500。
  机制包 Wiki 的 2150 / 1800 / 1700 / 1700 / 1800 与因子上浮 +950 / +600 / +500 / +500 / +600
  属另一层口径，**不采用为主口径**。❓`single_mode_scenario.max_*` 与运行时 `max_stats` 的关系。

### 6.1 教诲分配 / 融合决策方案（2026-10-31 拍板）

> 目标：融合不产生运行时组合维度；分配保持小规模、可精确枚举。

**融合：配置 + 可选覆盖，不进决策树**

- 默认固定预设（可在线覆盖一次）：
  - year2：`101+601`（羁绊+特化）、`201+701`（得意率+研钻）；
  - year3：`401+801`（助力+协力）、`301+901`（Hint+不屈）、`501+1001`（体力+两道）。
- turn 23 / 47 结束时先应用融合配置，再进入 5 槽分配；若在线覆盖，先 `apply_fusion_plan` 再分配。
- 配置加载校验：year2 恰好 2 个基础槽、year3 必须是剩余 3 个、每个新教诲只用一次、不能重复融合。

**分配：每窗口独立，`5! = 120` 全枚举**

- turn 2 / 11 / 35：5 个基础槽；turn 23：2 融合 + 3 基础；turn 47 / 59：5 个终态槽。
- 每个窗口只按**当前槽位效果**估值，不为未来融合做铺垫（融合同时重排）。
- 改派窗口额外包含“保持不变”一个候选。
- 价值矩阵 `score[slot][act]` 的主要特征：
  - `card_count` / `npc_count` / `担当数 = 卡 + NPC`；
  - 预计训练次数、稽古次数、主属性 / 副属性权重；
  - 演目 Lv、gauge、是否排练激活、失败风险、是否合宿窗口；
  - 非友情训练频率（助力）、体力消耗（体力）、灵感 / 得意覆盖率（卡数）。
- **硬约束**：turn 47 / 59 的 `401+801` 放到**担当数最多的演目**（每个担当各一处分身）；
  并列处理以后再定（主流卡组无此情况）。
- **软约束**：`101+601` 的合宿“额外 1 人”同样按担当数计算，仅在合宿窗口作为软分数，不与 401+801 抢硬约束。
- 求解：枚举 120 个排列，按 `Σ score` 排序；best 给在线 / 手动，top-K（K=8–16）给搜索根节点。

## 7. 随机轴与可复现

- 局面流 / 事件流：由 `BaseGame` 持有，每回合按 `(master, turn)` 派生。
- 策略流：本局面自持，动作结算与剧本机制随机从它取；`set_rule_master` 与回合边界重置。
- 决策流：只给 `Trainer`，不影响结算随机。
- `fork_for_rollout`：克隆 + 注入 rollout 主种子；任何不由传入 rng 驱动的流必须在这里重置。
