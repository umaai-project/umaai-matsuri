## 1. 回合与阶段

> 口径：本文 turn 一律 **0 基**（`turn ∈ [0, 77]`）；`master.mdb` / 游戏内显示为 1 基，必要时在括号内保留原始值。

- 回合范围：`turn ∈ [0, 77]`（全 78 回合）；Senior 10 月後半最终结算在 `turn 67`。
- 三次剧本结算 / 進捗発表会：`turn 23 / 47 / 67`，门槛全演目 Lv `3 / 5 / 6`
  （`single_mode_15_schedule`；`need_act_num = 5`）。
- 合宿窗口：`turn 12–15 / 36–39 / 60–63`（0 基；Junior 即有夏合宿）。
- **合宿规则**（官方帮助）：合宿中**每回合都能进行演目稽古**；合宿中**演目 Lv 不上升**；
  合宿结束后**全演目 Lv +1**；合宿中无体力回复事件（「不回体」仅指没有合宿内回体事件）。
- **合宿延长**（user 实测 2026-10-26）：基础 4 回合；若合宿窗口内出现目标比赛或强制休息，
  合宿按回合顺延，直到该年累计 **4 个非比赛合宿回合**。比赛回合与强制休息回合不计入这 4 个。
  - 例：樱花进王顺延到 10 月前半（0 基 turn 66）；凯斯奇迹 9 月前半比赛、9 月后半比赛触发强制休息，
    10 月前半仍有顺延合宿回合。
  - **全演目 Lv +1** 的结算点**暂定固定为该年 8 月后半结束（turn 15 / 39 / 63 结束时）**，
    不随顺延推迟；视频「3 个演目各 +1」按样本截断，不采用。
  - **延长回合属性（U18，2026-10-31）**：**所有年份的延长回合都算合宿（全部为排练）**；
    第 1 年的延长回合也按第 1 年合宿规则（正常休息 / 可外出 / 可有支援卡事件）。
  - **离线模拟口径（2026-10-31）**：本阶段只做离线模拟，只需与在线行为一致，不依赖在线数据下发；
    合宿窗口与所有年份的延长回合按**硬编码**判定，`summer_camp_remain_turn_num` 只作对照。
- **合宿外出 / 休息（U33，2026-10-31；休息范围 2026-11-01 细化）**：**第 2/3 年合宿不能普通 / 友人外出**；
  **合宿版休息只在原本夏合宿期间＝Classic/Senior 的 7–8 月，延长回合休息为普通休息**
  （`shuntaisai_memo` 2026-10-31；外出仍按 U33 全程不可，含延长段）；
  **第 1 年正常休息，可普通 / 友人外出，可有支援卡事件**。
- **合宿期事件**（user 2026-10-30）：**第 1 年**合宿支援卡连续事件 + 普通马娘事件都发生；
  **第 2/3 年**常规合宿回合两类都不发生；**延长段的个体固定事件仍发生**；
  延长段是否触发支援卡连续事件待测（U19）。**抑制表 / 不可发生连续事件回合表由剧本自持重做，
  不复用引擎 `no_event_turns`**（见 §5.3）。
- 本番后：剧情结束，但仍可攒 gauge / 执行演目稽古直到 `turn 77`（URA 收尾）。**URA 期不做
  「全部训练变稽古」的特殊化**（与合宿不同）：剧本结算已结束，训练 / gauge / 稽古 / 演目 Lv 升级
  回到日常机制（用户 2026-11-01 确认）。
- 阶段机（内部强类型，对外 `StageId`）：S3 定为五阶段 `Begin(0) → Distribute(3) → Train(1) →
  AfterTrain(4) → End(2)`（**号只增不改**）；比赛 / 合宿 / 発表会 / 本番 / URA 收尾是**回合类型**
  （`TurnPlan`），不各开阶段；`Race / ActTrain / Outing` 是 `Train` 阶段里的动作，`CheckPoint` /
  合宿 +1 / 教诲分配都在 `End`。**担当分配是建局 / NPC 加入时的一次性动作，不是阶段**（见 §2.1）。

**回合结构（S3 已落地）**

- 阶段机（内部强类型 `Stage`，对外只投影 `StageId`）：一回合固定
  `Begin(0) → Distribute(3) → Train(1) → AfterTrain(4) → End(2)`；**号只增不改**。
- 回合类型 / 边界由 `TurnPlan`（每回合 `Begin` 派生一次）表达，**不各开阶段**：
  `race`（目标赛 / URA 决赛回合，分类不变）、`ura_race`（73/75/77）、
  `ura_period`（本番后 ≥68，由 `schedule` 末项 +1 派生）、
  `camp_year / camp_zone / camp_regular / camp_extended / camp_rest`、
  `camp_level_up`（15/39/63）、`check_point`（23/47/67 → 0/1/2）、
  `advice_window`（2/11/23/35/47/59）。
- **合宿窗口与延长算法**：从 `window.start` 开始本次合宿；每回合 `End` 计数，
  **目标赛 / 强制休息回合不计入**，计满**窗口长度（= 4）**才结束 → 顺延自动成立；
  `camp_rest` = 原窗口内 && 年次 ≥ 1（Junior 与延长段为普通休息）；
  **全演目 +1 仍固定日历时点 turn 15/39/63**（不随顺延推迟；`plan.camp_level_up` 供 S5 结算）。
- **马娘特殊事件（强制休息，临时口径）**：目标赛回合可被固定事件改为**实际执行休息**（退赛）——
  回合仍按 `plan.race = true` 分类，但**不产生比赛事件 / 奖励**，实际动作是休息；
  目前只登记凯斯奇迹 T65（键 = `chara_id = uma_id / 100`），等引擎「马娘特殊事件记录」
  数据结构落地后改为读引擎数据（涵盖其他异常事件）。
- **结算时机统一在 `End`（用户 2026-11-01 确认）**：発表会 / 本番 buff 与一次性奖励、合宿全演目 +1，
  以及**教诲分配 / 调整（含 turn 23/47 的転成）全部在 `End`**；顺序是**先剧本结算、后教诲分配 / 调整**。
  turn 67（本番）是**正常回合**，本番结算在 `End` 阶段。
- **合宿回合**：5 个训练动作**全部变演目稽古**（不受 gauge 是否满影响）；这些稽古**不改变演目 Lv、
  不进演目槽**；Lv 只在该年固定结算点 +1。
- 比赛 / 演目稽古 / 出行是 `Train` 阶段的**动作**（S4 落），不为它们单开阶段。

## 2. 资源与账本

- 剧本资源：**5 条演目ゲージ**（对应 5 训练）+ **5 个演目 Lv**。
- gauge 上限 **5**（真机 `NeedActGauge = 5`）；不随回合自然减少。
- 入账（2026-10-31）：对应演目担当**每参与 1 人 +1**；**闪彩担当 +2**（同场其他仍 +1）；
  **目标比赛 +4**（按 4 次 +1 入账，落点与休息 / 外出同一三则：**演目 Lv 最低 → 槽最低 → 仍相同按 速→耐→力→毅力→智**，满槽跳过；并列逐次分摊）；
  休息 / 外出 / 非目标比赛 **+1**（落点同上三则）。
- 消费：gauge 满后对应训练变演目稽古；**成功**时该演目 `Lv +1`、gauge 清零；
  **失败 = 训练失败**：照常触发失败后事件、不给属性收益，且 **完全无效——槽不动、Lv 不升**
  （2026-11-01 修正，`shuntaisai_memo` 口径）。
- 可延期：亮起后不必立即执行、不会过期；多个演目同时亮起可任选其一，其他不消失。
  **所有亮起位置都会锁人**（见 §2.1）。
- **S5 已实现（2026-11-01）**：`game/mod.rs` `gain_lowest_act_gauge`（三则 + 满槽跳过）/ `gain_act_gauge`；
  训练入槽 `train.rs` `gain_training_gauge`；目标赛 / 休息 / 出行入槽在 `action.rs`；稽古成功
  `settle_training` 里 `add_act_level` + 槽清零（合宿不升不清）——gauge 入账 / 消费闭环已落。
- 跨回合状态存局面字段，不存阶段枚举。
- Senior 期各演目再 **+1 名担当**（memo；待真机）。
- 剧本链接角色（固定演目担当）按**固定演目**判定 gauge / 教え / 稽古登场，不按支援卡类型。
- 真机 `ActInfoArray` 每个元素：`ActType / ActGauge / Level / NeedActGauge / ActTrainingState /
  AdviceId / FriendOutingGainActLevel`；`ActType` 是主键（1–5），不是 `command_id`。

### 2.1 担当分配（一次性）与每回合人头分布（阶段）

> 2026-10-30 方案讨论拍板；实现时不要把两者混成一个阶段。

- **担当分配**是剧本开始建局时（含 turn 2 第一批 NPC 加入、turn 47 大成功第二批 +5）完成的**一次性动作**，
  **不是游戏阶段、不产生决策点、不占回合**。五步流水线（link 钉位 → 卡按类型本位 → 整位 2 张卡容量 →
  外派链 → NPC 每演目 1 人 → 吾妻余额）只在这里生效。
- **每训练位最多 2 张卡**只在担当分配时成立；进入训练人头分布后不受该限制，只受
  **每训练位最多 5 人（含 NPC）**约束。
- **每回合人头分布**才是阶段（`Distribute`）：
  - 普通训练：担当支援卡与 NPC 都按基础库算法（卡按类型 + 剧本得意率加成加权；NPC 无得意率、等权随机；
    均先判不在率）。
  - **任何槽满亮起的演目**：其担当卡与担当 NPC **必定出现并锁定在担当训练位**，**不判不在率**；
    **所有亮起位置都锁人**（不只当前要执行的那个）。只有**分身**和**未亮起位置**的担当可以跑到其他训练；
    因此亮起过多会减少其他位置的期望人头，**是否亮起 / 何时执行有策略性**（2026-10-31）。
  - 亮起位置不能做普通训练，只能选对应 `ActTrain`；多个亮起时所有亮起都可选。
  - 排练位上的非担当 NPC 仍可随机同框，但不计加槽人数、不推槽（§2.3）。
- **`distribute` 整体重写**：不复用默认 `distribute_all` 的“全员同权随机”语义；`sample_bucket` /
  `absent_weight` 形态可复用。NPC 不在率先按 `absent_weight = 50`（约 9.1%）实现，待真机（U29）。
- **分身**：在 `distribution` 中以**同一人头下标重复占位**（不新建人头）；按占位逐个计数、不去重；
  唯一不生效的卡效果是友情（非本职训练位不亮彩圈）。详见 [`matsuri_memo_cn.md`](matsuri_memo_cn.md) §3.5。

### 2.2 人头的实现形态（S4 前置，已落）

- **剧本人头 `MatsuriPerson`** = 引擎通用 `BasePerson` + 剧本字段：`act`（担当演目）、`origin`
  （来源：卡 / 友人 / 编成外神驹 / 理事长 `Yayoi` / 记者）、`avail_turn`（可用回合）、`needs_great_success`
  （第 2 批神驹需 Classic 発表会大成功）。契约 `Person` 的 impl 整体在 `game/traits.rs`，
  `MatsuriPerson` 的构造 / 查询在 `game/person.rs`。
- **`PersonOrigin` 与 `PersonType` 分工**：`PersonType` 是引擎契约语义（缺省可用性 / 不在率 /
  分布顺序 / 红点 / 闪彩等，剧本不能扩展）；`PersonOrigin` 是剧本侧标签，构造时**单向决定**
  `PersonType`（Card→Card / Friend→ScenarioCard / Guest→Npc / Yayoi→Yayoi / Reporter→Reporter）。
  引擎只看 `PersonType`、剧本只看 `PersonOrigin`，互不反推。
- **名单布局**：卡组人头（`persons` 前缀与 `deck` 同序，含友人卡）→ 理事长 → 记者 → 编成外神驹
  「第 1 批 5 名固定 + 带吾妻余额 1」→「第 2 批 5 名」。**两批神驹规则上同质**（`PersonOrigin::Guest`），
  只靠 `avail_turn`（2 / 48）与 `needs_great_success` 区分；理事长 / 记者按引擎基础局默认处理。
- **担当 ≠ 站位**：`act` 是建局一次性分配结果（link 钉位 → 卡按类型本位 → 外派链 → NPC 每演目 1 人 →
  余额），不随回合变；每回合站位（`distribution`）归 S5。
- **同 `chara_id` 约束（模拟口径）**：不允许两个不同人头同 `chara_id`（同 chara 只能以
  `distribution` 重复占位的形式作分身）。编成卡 / 育成马娘 / 5 名 link 角色 / 已出现人头都会
  从「随机非 link 角色」候选中排除；**育成马娘本身是 link 角色时，该演目固定神驹换成随机非 link 顶替**。
- **随机非 link 角色取人（离线简化）**：真机从马娘池随机抓；本模拟从 `chara_id` 1001 起按序取
  第一个满足条件者（见 `stubs.md` 登记，接在线模式时可换成随机）。

### 2.3 编成检测（S4 前置，已落）

担当机制对编成敏感，建局前统一检查（`game/deck.rs` `inspect_deck`；宿主可先用它自查）。
**禁止项**拒绝建局（`newgame` 返回 `Err`）；**警告项**不阻止建局，随 `MatsuriGame::deck_warnings`
/ `MatsuriView.deck_warnings` 下发（CLI 在跑局前打印）。

| 类 | 项 | 内容 |
|---|---|---|
| 禁止 | E1 | 没带 SSR 吾妻 |
| 禁止 | E2 | 友人卡多于 1 张 |
| 禁止 | E3 | 带 SSR 吾妻以外的友人卡（含 R 吾妻） |
| 禁止 | E4 | 卡组不符合通用规则：**必须 6 张**（5 普通支援卡 + 1 友人）/ 无重复人物 / 不含担当马娘 / 卡类型正确（**含团队卡拒绝**） |
| 警告 | W1 | 剧本 link 卡类型与其固定演目不一致（如速重炮被钉在力量演目；**link=固定演目本身是合理情况**） |
| 警告 | W2 | 同一类型卡 ≥ 3 张（整位容量 2 张，必然外派） |
| 警告 | W3 | 卡被外派到非本职演目（担当位置溢出到别的训练；同类 <3 张时也可能发生，故与 W2 分开） |
| 警告 | W4 | 编成支援卡类型 < 5 种（含友人；演目 Lv 效果的「5 种卡」列无法发动） |
| 警告 | W10 | 各演目「卡 + 第 1 批 NPC」人物数极差 ≥ 2（担当分布不均衡；**唯一条件**） |

- **不警告**：某演目 0 张支援卡（典型 21101 不带根卡，可接受）；link=固定演目 / 育成马娘是
  link 角色导致的神驹顶替（合理情况）；link 卡类型与固定演目一致（零增量）。
- **剧本友人（吾妻）也是剧本 link 角色，但不参与 roster / 担当分配**；W4 的「类型种数」按
  含友人计（与 `condition_value = 5` 的「含友人」口径一致），W1 只对参与担当的支援卡判定。
- 检测报告同时返回卡侧担当分配结果，`roster` 直接复用（避免重复计算）。

## 3. 训练与加成

### 3.1 命令与基础值

**计算公式（`memo` 2026-10-31，主 / 副属性拆分，上段）**

- **主属性**：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计) × (1 + 主获得量合计)) - 下段`。
- **副属性**：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + 副获得量合计)) - 下段`；
  **副获得量与训练效果同层加算**（不是再乘一层；`memo` 2026-10-31）。
- SP：`floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + SP训练效果)) - 下段`。
- **演目稽古：全五维基础各 +10**（act_lv `all_status_bonus`，Lv1–10 恒 10）——**2026-11-01 拍板：
  加在上层乘区之后（flat，不受乘区 / 上昇量上限影响）**；未使用维也 +10。
- 下段 = 通常通り：普通训练取该训练位 / 该训练 Lv 的基础值；稽古取当期档（§3.2）。
- 友情合计（仅友情训练）：駿大祭 buff、協力教え、稽古的演目 Lv 效果、得意率転成（稽古）。
- 训练效果合计：助力（非友情时）、助力支撑、両道（稽古）、不屈（稽古）。
- 主获得量合计：特化、絆（稽古）、絆転成（稽古）。
- 副获得量合计：両道（SP 除外；与训练效果同层加算）。
- 教え效果按「教え绑定的演目担当**参与人数**」叠加；**効果等级 = 所绑定演目的 Lv（1–10）**，与训练种类无关；
  **改派后随新演目的 Lv 改变**。例外：**絆 +3 为平摊、不按人数叠加**（见下）。
- **两层口径（2026-10-31）**：**下层直接用基础库原始公式（`default_calc_training_value`）**算普通训练值；
  卡面 / 通用项（友情、训练效果、人数、干劲、成长率等）都在下层。**剧本加成相关的数值全部体现在上层**：
  演目 Lv 效果、教え、発表会 buff、稽古 +10 等按上面的“友情合计 / 训练效果合计 / 获得量合计”叠加，
  **不重复计入下层已有项**。每个剧本 buff 的乘区归属按规则表落实现；两层结构已定，具体数值细节仍可复核。
- **上层实现（S5）**：`game/train.rs` `training_upper` 用剧本侧合计按上式算主 / 副 / SP 增量，
  再按**上昇量上限**封顶；**上限 = 规则 100 + 特化教え `status_limit`（按参与担当聚合）+
  稽古且 5 种卡时该演目 Lv9/10 的 `status_limit`；SP 上限同法并叠加 `sp_limit`**（2026-11-01 拍板；
  属性基础上限 2200 组是否同步上抬未确认，见 `stubs.md`）。
  体力：稽古按体力教え / 転成 `keiko_vital_cost_drop` 百分比降耗；URA 训练再 +30 体 / +1 干劲（本番演出）。
- **取整（2026-10-30）**：所有乘算收益（比赛加成、剧本倍率等）统一 **floor**，不用 round；
  目标赛 SP `72 × 1.3 = 93.6 → 93` 已按此口径。
- **演目稽古基础值按时期两档**（Junior / Classic 及以后；见 §3.2 注）；**无 Senior 第三档**
  （第二档覆盖 Classic 与 Senior，U02 2026-11-01 收口）；**基础值没有 Lv2–10 维度**（`command_level` 只查
  演目效果 / UI；mdb 5101–5105 只有 Lv1 一组行；「稽古 +10」来自 `act_effect 105`，Lv1–10 恒 10）。

### 3.3 教え（教え）加成

- 教え作用于「演目担当」（含编成外神駒），不是全体人头；羁绊教え只对编成支援卡生效。
- 效果按「教え绑定的演目担当参与人数」叠加（例：助力担当 2 人则助力效果 2 倍）；
  演目 Lv 取**教え绑定的演目**，与训练种类无关。**絆の教え例外：+3 平摊、不按人数叠加**，
  作用于全编组卡并与训练本身的绊上升合算（参加友人 +7 / 参加非友人 +10 / 不参加 +3；愛嬌合计再 +2）。
- 転成效果同样按参与担当人数叠加。
- 实现口径（memo 调查项）：特化的基础上限也作用于 SP 上限；稽古 +10 不吃非得意加成；
  转成的「灵感 +1」= Hint Lv+1；**Lv4+ 全灵感发动不含嘉宾**；
  研鑽发生率**1 回合 1 次共通掷骰、`p = r(绑定演目Lv)`、不按担当人数加算**（`memo` 2026-10-31，推翻旧口径），
  掷中则所有该演目担当参与的成功训练都触发，仅成功时结算。
- **S5 实现口径（2026-11-01）**：`game/advice.rs` `advice_slot_effect` 按「新教诲效果（绑定演目 Lv）+
  被消耗基础教诲的固定転成升级效果」聚合；`participant_advice` 遍历训练位占位按参与担当人数叠加
  （絆 +3 取 max 平摊）；助力支撑 = 3 次内训练效果 +5%（`rules.assist_support`，再次获得重置）；
  研鑽追加稽古在 `Begin` 用策略流预掷、训练成功且绑定演目担当参与时按 50/50 上 / 下档结算

  下档：属性 +5 / 体力 +5）。教诲 5 槽永远满、效果随改派即时换级。

## 5. 事件

### 5.1 伝受 / 転成

- `single_mode_15_advice_recommend`：turn **2 / 11 / 23 / 35 / 47 / 59** 是可调整窗口（原始 1 基值 3 / 12 / 24 / 36 / 48 / 60）。
  - turn 2：获得 5 个基础教诲（101–501），**必须给 5 个演目各分配 1 个（不能空）**；
  - turn 11 / 35 / 59：合宿直前（6 月後半）**可选重排**，也可保持原样；
  - turn 23 结束（第二年初）：从 5 个基础教诲中**选 2 个**，分别与 601 特化 / 701 研鑽 融合；随后 5 槽重排；
  - turn 47 结束（第三年初）：**剩余 3 个**基础教诲分别与 801 協力 / 901 不屈 / 1001 両道 融合；随后 5 槽重排。
- **槽位模型（2026-10-31）**：永远 5 个教诲槽（对应 5 演目），不是「10 选 5」；追加 5 种不是独立槽位，只作融合对象。

## 7. 随机轴与可复现

- 局面流 / 事件流：由 `BaseGame` 持有，每回合按 `(master, turn)` 派生。
- 策略流：本局面自持，动作结算与剧本机制随机从它取；`set_rule_master` 与回合边界重置。
  S5 里**追加稽古预掷**（`Begin`）与训练结算走策略流；**每回合人头分布 / 灵感分配**走回合固定流
  （`streams.turn_fixed`，与引擎基础局 `distribute_all` 同轴）。
- 决策流：只给 `Trainer`，不影响结算随机。
- `fork_for_rollout`：克隆 + 注入 rollout 主种子；任何不由传入 rng 驱动的流必须在这里重置。
