# ADR-0011: 模块环与字段泄漏收敛方案（待定）

- **状态**：提议中（尚未实施）
- **日期**：2026-11-27
- **关联**：`matsuri-core`（`game` / `trainer` / `value` / `search`）、`matsuri-ai`、`matsuri-tools`、`deslop-please`

## 背景（Context）

`deslop-please`（架构 linter：deep modules / narrow interfaces）首扫 35 条 error。2026-11-27 已落地 `.deslop-please.allow` 豁免 22 条（`MatsuriData` 只读数据表 16、`config`/`data` 2、`OnlineSession::profile`、`Case::records`、`wide-directory`、`long-file`）。剩余 11 条：

| 类型 | 条数 | 内容 |
| --- | ---: | --- |
| `module-cycle` | 3 | `game↔trainer↔value`、`game` 内部 10 模块环、`deck↔roster` |
| `tangle` | 1 | `MatsuriGame ↔ Action ↔ unfused_act_of ↔ MatsuriTrainer ↔ Model`（跨 7 模块） |
| `field-leak` | 7 | `MatsuriGame` 的 `base` / `check_points` / `deck_warnings` / `event_cursor` / `event_log` / `plan` / `stage` |

### 已完成：P2 值语义收口（2026-11-27）

`MatsuriGame::advice` 与 `event_queue` 已收口为值语义接口（`crates/matsuri-core/src/game/mod.rs`）：

- advice：`advice_slots` / `advice_fused` / `advice_acquired` / `advice_state` / `set_advice` / `set_advice_fused` / `ensure_base_advice`；
- event_queue：`has_pending_event` / `take_event_at_cursor` / `set_pending_events` / `reset_event_queue`。

判据：`deslop-please` 的 `field-leak` 把「通过方法访问」也算泄漏（报 `through MatsuriGame::advice_mut`），因此返回 `&字段` 的 getter 无效，必须让外部拿不到结构本身。errors 由 13 降到 11。

## 决策（Decision）

P1 按代价从小到大分三阶段；每阶段以 `deslop-please --allow .deslop-please.allow` 的报错数下降为验收，且行为与基线分不变。

### 阶段一：`deck ↔ roster` 单向化（最小）

- 现状：`deck::inspect_deck` 调 `roster::assign_card_acts`；`roster` 反向使用 `deck` 的 `inspect_deck` / `DeckReport` 等 9 项。
- 方案：`assign_card_acts` 归 roster；`deck` 只产出校验报告；「deck 校验 → roster 分配」由 `game/mod.rs` 编排。
- 验收：该 `module-cycle` 消失。

### 阶段二：`game` 内部 10 模块环收口

- 现状：`action / advice / diag / distribute / event / settle / stage / train / traits / view` 互相调用 `impl MatsuriGame` 的 inherent 方法（`stage → diag`、`action → advice/train`、`advice → traits` 等）。
- 方案（二选一，先画模块图再定）：
  1. **门面化**：跨模块协作只经 `mod.rs` 的少数阶段入口（如 `begin` / `step` / `end`），其余方法 `pub(crate)` 且只允许 `mod.rs` 调用；
  2. **抽 `StageMachine`**：阶段编排独立成类型，`MatsuriGame` 退回状态容器。
- 验收：该 `module-cycle` 消失，测试全绿。

### 阶段三：`game ↔ trainer ↔ value` 与 `tangle`

- 现状：`value::Model` 直接吃 `&MatsuriGame`（82 项依赖）；`game` 的 traits 实现构造 `MatsuriTrainer`；trainer 持有 `Model`。
- 方案：`value` 输入收窄为只读快照（复用 `MatsuriView`，或定义只含估值查询的 `ValueInput` trait）；trainer 构造上移到装配层（bin / cli / session），`game` 不再 `new` trainer。
- 验收：`module-cycle` 与 `tangle` 同时消失，`bench baseline` 不漂移。

### 剩余 7 条 `field-leak`

随阶段二、三逐步收口：`base` / `config` / `data` 等只读面优先，`event_cursor` / `event_log` / `plan` / `stage` 等状态字段按 P2 同口径逐个改值语义接口。

## 影响（Consequences）

- 收益：模块边界重新可依赖；`deslop-please` 从 11 条向 0 收敛，`.deslop-please.allow` 只减不增。
- 代价：阶段二、三改动面大（`value` 全部调用点、`game` 阶段机），需独立会话推进并重跑基线。
- 约束：每阶段保持行为与基线分不变；不得用 `#[allow]` 或挪文件绕过 linter（见根 `AGENTS.md` 架构检查纪律）。
- 状态：**待定，先不做**（用户 2026-11-27「先不做，按文档规则把他列为待定方案文档」）。
