# ADR-0004: 引擎零侵入与跨仓边界

- **状态**：已采纳
- **日期**：2026-10-30（2026-11-06 补强）
- **关联**：`umaai_next/`、`matsuri-core`、[ARCHITECTURE.md](../../../ARCHITECTURE.md)、[mechanism.md](../../mechanism.md)

## 背景（Context）

本仓围绕 `umaai_next` 公共引擎开发新剧本，若为剧本特定逻辑频繁修改引擎或私造私有协议字段，会推高跨仓维护与 submodule 同步成本，甚至污染其他剧本（如擅自引入协议中不存在的 `ill_guard_count`）。

## 决策（Decision）

1. **剧本专属逻辑自持**：合宿判定、比赛奖励表、演目、教诲、発表会及特殊事件表等剧本专属机制全部留在 `matsuri-*`，**非必要不动 `umaai_next/`**。
2. **通用能力先入引擎**：仅跨剧本通用的底层机制（如 `ExtraStatus`、比赛 floor、`lucky_count`、无状态钩子 `finish_root_stage` 等）才合入 `umaai_next/`，剧本仓复用既有接口。
3. **禁止私造协议字段**：禁止在剧本仓发明协议中不存在的状态字段（如弃用 `ill_guard_count`，改接引擎既有的 `lucky_count` 拦截生病与变胖）。

## 影响（Consequences）

- 保持 `umaai_next/` 对多剧本的通用性与稳定性，降低跨仓合并冲突。
- 剧本侧需自行承担状态机与规则组合，但演进完全独立、无需等待引擎发版。
