# ADR-0006: 在线无状态帧还原与协议容错契约

- **状态**：已采纳
- **日期**：2026-11-08（2026-11-13 补强）
- **关联**：`matsuri-ai`、[online_protocol.md](../../online_protocol.md)、[changelog.md](../../changelog.md)

## 背景（Context）

真机在线游玩时，玩家可能反复进出同一状态、读档重开，且上游小黑板插件（`URA_Plugins`）的卡表数据更新往往滞后于 AI 数据。若沿用引擎有状态的 `Session::step_turn`、对同回合决策去重，或对帧内非关键缺失直接 `bail`，会导致面板停在旧建议或整局无法决策。

## 决策（Decision）

1. **无状态逐帧还原与决策**：在线不走 `Session::step_turn`，改为无状态循环逐帧重建局面；撤除同回合决策去重，每张内容有变的新帧均重新决策并输出（入口阶段按决策面而非单独按 `isAfterTraining` 判定，教诲搜索根阶段按 `plan.advice_window` 判定）。
2. **全量 `charaEffects` 协议**：取消早期 `illEffects`，Base 系剧本帧恒输出去重保序的全量 `charaEffects`，接收端显式映射病种（1–6），无兼容层。
3. **静默容错与未登场保留**：帧内 `charaId = 0` 或局部越界条目（`actType` / `scheduleId` / 分布异常点）静默降级并仅用 `diag!` 留痕，不拒绝整帧也不输出 `notes`；仅当 AI 本地也缺卡/缺角色时才拒绝并提示更新。`restore_persons` 保留建局名单中尚未登场（`avail_turn = 48`）的神驹条目，避免 rollout 低估期望。

## 影响（Consequences）

- 保证玩家反复切屏、读档或插件数据短暂滞后时，在线 AI 仍能给出正确建议与稳定的期望分。
- 插件 DLL 与 `matsuri-ai` 需同步遵循 `charaEffects` 契约，不保留旧字段兼容代码。
