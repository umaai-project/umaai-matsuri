---
name: grilling
description: "就某个计划、决策或想法持续追问用户，帮助对思考做压力测试，或响应各类追问/审视触发词。"
---

持续追问用户，直到双方达成共识。将问题空间绘制成一棵**设计树（design tree）**：每项决策都会分叉出依赖于它的下游决策。

按**轮次（rounds）**推进这棵树。**前沿（frontier）**指所有前置条件已敲定的决策——也就是你*现在*无需猜测未知答案就能直接提出的问题。每一轮一次性提出整个前沿：为每个问题编号，并给出你的推荐答案，然后等待用户回复后再进入下一轮。

每轮按如下格式组织：

```markdown
❓ **Q1** - **<问题标题>**: <问题正文，可包含多段说明与多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文，可包含多段说明与多个选项>

➡️ <你的推荐答案>
```

措辞时尽量让用户回答“是/同意”即可直接采纳你的推荐答案。

用户每回答一轮，都会重塑整棵设计树：已敲定的决策会把前沿向外推进，解锁依赖它们的后续问题。重新计算前沿并发起下一轮追问。凡是答案仍依赖于本轮尚未敲定问题的问题，都应留到*下一轮*再问，不要混在本轮。

查明**客观事实**是你的职责，绝不是用户的职责。当某个前沿问题需要从环境（文件系统、工具等）获取事实时，派发一个拥有全新上下文窗口的子代理去查明，不要向用户询问任何你自己能查到的问题。不要为此阻塞整轮：正在进行的调研视为未敲定的前置条件，只让下游依赖它的问题等待子代理回报，其余前沿问题照常在本轮提出。**决策权**属于用户：把每个决策交由用户拍板并等待其答复。

当前沿为空时本次追问即告完成：设计树的每一条分支都已访问，没有任何被默默假设的空白。在用户确认双方已达成共识之前，不要擅自开始实施。
