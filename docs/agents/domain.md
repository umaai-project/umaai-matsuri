# 领域文档（Domain Docs）

本文件规定工程技能在探索代码库时如何读取与使用领域文档。

## 探索前先阅读以下文档

- 仓库根目录的 **`GLOSSARY.md`**
- **`docs/adr/`**：阅读与即将改动区域相关的 ADR（架构决策记录）。

如果上述文件或目录尚不存在，**静默继续即可**，不要将其缺失标记为问题，也不要预先建议创建它们。`/domain-modeling` 技能（通过 `/grill-with-docs` 与 `/improve-codebase-architecture` 触发）会在术语或决策真正落地时按需创建它们。

## 目录结构

本仓采用单上下文仓库布局：

```
/
├── GLOSSARY.md
├── docs/adr/
│   └── 0001-<decision-title>.md
└── crates/
```

## 严格使用术语表词汇

当输出内容涉及领域概念（如 Issue 标题、重构提案、假设、测试命名）时，应使用 `GLOSSARY.md` 中定义的标准术语，不要擅自替换为术语表明确避免的同义词。

如果所需的领域概念尚未收录在术语表中，通常意味着两种情况之一：要么正在引入项目未使用的自造词（需重新斟酌），要么确实存在术语缺口（记录下来以备 `/domain-modeling` 补充）。

## 显式提示 ADR 冲突

如果输出方案与现有 ADR 相矛盾，必须显式指出，切勿静默覆盖：

> _与 ADR-0001（<决策简述>）存在冲突，但值得重新讨论的原因是……_
