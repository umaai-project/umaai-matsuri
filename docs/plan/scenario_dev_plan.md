## 0. 本地开发环境（引擎并列仓，前置）

本仓**不 vendor 引擎代码**。workspace `Cargo.toml` 以 path 依赖引用引擎仓的四个 crate：
`umaai-core` / `umasim` / `umaai`（`matsuri-core` 需要）与 `umaai-cli`（仅 `matsuri-cli` 需要）。
因此**本地开发第一步是把引擎仓 `umaai-next` 拉取到当前工作区**，与 `umaai-matsuri` 并列；
引擎仓不存在时，`cargo` 任何命令都无法解析依赖（不是可选步骤，也不是 submodule）。

### 0.1 目录约定

- 工作区根下并列两个目录：`umaai-matsuri/`（本仓）与 `umaai_next/`（引擎仓）。
- 目录名必须是 `umaai_next`（下划线）：path 依赖写死 `../umaai_next/...`；若克隆成连字符目录名，
  需同步改 workspace `Cargo.toml` 里四条 path 依赖。
- 首次拉取（在工作区根执行）：

```powershell
git clone git@github.com:umaai-project/umaai-next.git umaai_next
```

### 0.2 版本与基线

- 引擎仓停在 `main`；本仓基线 = 引擎 `main` 当前提交。开发期随引擎推进定期 `git pull`，
  拉取后先跑 §0.4 自检再继续改动。
- 引擎仓工作树的未提交改动目前只在 `docs/notes/`（`matsuri_scenario_preview.md` 整理等），
  只影响文档；剧本实现只消费引擎 crate，机制口径以引擎 `main` 提交为准。
- 引擎 `docs/scenario/{README,repo_form,dev_process,perf_plan,contracts}.md` 与
  `docs/notes/matsuri_scenario_preview.md` 随引擎仓一起拉取，是本仓文档的外链对象（见
  [`../README.md`](../README.md) §2）。
- 稳定期切 git tag（同一 repo、同一 tag）；下游（Web / Android）另加 `default-features = false`。

### 0.3 纪律

- 不 fork 引擎、不在引擎仓新增剧本 crate；接入本剧本时引擎仓 `git diff` 为空。
- 确需新能力时回引擎仓按「带默认实现、非破坏」加钩子，再回本仓消费。
- 引擎静态数据已拷入 `data/`（`ai_config.toml` + 六张静态表 + 剧本资产 / 配置默认层），
  跑局不依赖引擎仓 `gamedata/`；引擎仓只需存在且能编译。

### 0.4 环境自检（在 `umaai-matsuri/` 根执行）

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets --offline -- -D warnings
cargo test --workspace --release --offline
```

- 三条全绿即环境可用；`--offline` 走本地 registry 缓存，首次编译前需先在有网环境完成一次
  `cargo fetch`（改 registry 前先请用户提权）。
- 同一 target 目录一次只跑一个 cargo（并发会互等锁，表现为卡死）。
