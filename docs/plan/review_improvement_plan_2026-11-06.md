## 0. 一页结论

复盘不该按「棋类 AI 教学」来设计，因为我们有四个不同的前提：**没有对手、状态转移随机、目标是连续分数最大化且低容错、玩家动机是轻松游戏的同时追高分**。更贴切的参考对象是**无对手的连续计分竞技**（高尔夫 strokes gained、赛车计时遥测、速通分段），辅以扑克的「决策质量 ≠ 结果质量」、享乐型年度回顾的产品形态，以及教育心理学对反馈措辞的约束。

现有雏形比预想成熟得多：引擎接地、只挑关键手、运气/决策分离、非控制性语气、一致率不当评分，都已经实现。**真正缺的不是叙事层，而是三样数据**：玩家实际动作（现为状态差推断）、逐回合决策损失（`regret`）、以及参考轨迹与累计差值。

一句话定位：棋类复盘是训练工具，我们的应该是「赛后花絮 + 一个可选的岔路口」。玩家追高分的动力不需要我们教，我们只提供「哦，原来是这样」的顿悟感。

## 1. 背景：这些工具到底在做什么

本节写给不熟悉赛车 / 高尔夫分析的读者。它们不是「优化器」，而是**把一次完整过程拆成可计价的单位，再回答「分 / 时间丢在哪」的分析方法**。

### 1.1 高尔夫：Strokes Gained（每一杆值多少杆）

**运动形态**：一场 18 洞，每洞有标准杆 par（3 / 4 / 5），总杆数越低越好。球手不是互相干扰，而是各自打完比总杆数；变量是球位、距离、天气与自身执行。一次击球的结果（球停在哪）立刻成为下一杆的起点，所以**每一杆都直接计入总分**。

**传统统计为什么不够**：`fairways hit`、`greens in regulation`、`putts per round` 都是计数。300 码上球道和 250 码上球道记成一样；40 英尺两推和 3 英尺两推记成一样；更糟的是，铁杆打得好的人上果岭多、推杆数反而多，被统计惩罚。

**Broadie 的做法**（Mark Broadie，哥伦比亚商学院，*Every Shot Counts* 2014，基于 PGA Tour ShotLink 千万级击球记录）：给**每一个可能的球位**建一张基准表——「从这个位置进洞，平均还需要几杆」。位置由距离和 lie（球道 / 长草 / 沙坑 / 果岭）决定。典型基准：

| 球位 | 期望剩余杆数 |
|---|---|
| 450 码 par 4 发球台 | 4.10 |
| 球道 150 码 | 2.98 |
| 长草 150 码 | 3.15 |
| 沙坑 30 码 | 2.53 |
| 果岭 20 英尺 | 1.87 |
| 进洞 | 0.00 |

**公式**：`SG = V(击球前位置) − V(击球后位置) − 1`。减 1 是刚用掉的这一杆。例如从 4.10 的发球台打到 2.825 的球道：`4.10 − 2.825 − 1 = +0.275`，这一杆比基准好 0.275 杆。

**这本质上是动态规划**：书里专门讲了 Bellman 算法。`V` 就是 MDP 的价值函数，`SG` 是价值差分。一洞所有杆的 SG 相加等于该洞相对基准的差值，一轮相加等于总 SG。

**四类分解**：Off the Tee / Approach / Around the Green / Putting，四项相加等于 Total。Broadie 的关键发现是长杆（开球 + 攻果岭）解释约 **2/3** 的球手间分差；业余选手最大的漏分点在 125–175 码的 approach，而不是大家普遍以为的推杆。业余基准按差点分层（GolfMetrics 的 0–5 / 10–15 / 20+ HCP 各有表），消费端 Arccos / Shot Scope / Garmin 自动记录每杆起止位置并给出分类报告。

**两个值得注意的产物**：
- 「记分卡 75，技能分 70」——当天成绩与结构性水平被分开，差值来自当天波动。
- 它只回答「分丢在哪一类杆」，**不回答「怎么练」**（那是教练和课程的事）。

### 1.2 赛车计时遥测：Delta 曲线（时间丢在哪一米）

**运动形态**：计时赛 / 赛道日不是和对手撞，而是各自跑圈、比单圈时间。赛道被官方切成 3 个 sector，车队用高分辨率 GPS 进一步切成 50–200+ 个 micro-sector（对齐刹车区、弯心、出弯牵引区、直道）。

**Delta time 是什么**：取两圈，在赛道**每一个距离点**上把累计用时相减，画成一条沿赛道展开的曲线。线平 = 两圈一致；线往上爬 = 在那里丢时间；线往回落 = 追回来。MoTeC、Coach Dave Delta、Vetkuro、Purpl、karttrackapp 这类工具的核心就是这一条线，它回答的是「时间到底丢在哪一米」，而不是「你开得好不好」。

**三种形状**（行业里已成共识的读法）：

| 形状 | 含义 | 诊断 |
|---|---|---|
| 台阶 step | 平 → 某个弯突然抬升 → 又平 | 单点失误，有明确地址，只查那一处 |
| 斜坡 ramp | 沿一段直道缓慢持续爬升 | 不是某个动作，是上游状态在收赤字（出弯速度、齿比、胎况） |
| 锯齿 sawtooth | 进弯赚、出弯还回去，反复 | 两种驾驶风格在互相抵消，**不是失误** |

**Theoretical best / optimal lap**：把每个扇区（或微扇区）在这场比赛里的**历史最快**拼起来，得到「你已经证明自己跑得出、只是没串在同一圈」的理论最优圈速。`possible time save = 实际最佳圈 − 理论最优`。

**F1 车队的 constrained optimal**：直接把各段最佳相加是 fantasy，所以要加约束——排除异常帮助（黄旗、前车拖曳、那一圈本来拿不到的 DRS）、扣除 ERS 每圈能量预算与 120 kW 上限、考虑轮胎随圈衰减（新胎的 S1 不能和衰竭胎的 S3 拼）、交通、油量 / 引擎模式、风向与赛道 rubbering-in。输出形如：

> 实际 1:34.28；受约束最优 1:33.96；差 **+0.32**。主要损失：T9 出弯 +0.11、T13 刹车 +0.07、T3 弯心 +0.05。

**分段归因**：Coach Dave Delta 把一圈拆成 sequence（单弯或弯组），每个 sequence 再拆 Braking / Entry / Apex / Exit 四阶段，逐阶段给反馈。

**两条行规，对我们尤其重要**：
1. **flat delta ≠ 完美**，只等于「和参考一致」——两个都刹早 40 米的人之间是一条漂亮平线。所以「选一个值得比较的参考」是一半的技术。
2. **条件必须随数据保存**（温度、油量、胎况、交通）。早上的 1:57 和下午的 1:57 不是同一个 1:57。
3. 另有「delta 先读、其他通道后读」的次序：差值告诉你代价，速度 / 油门 / 刹车曲线才告诉原因。

### 1.3 速通分段：LiveSplit（累计 delta 与理论上限）

把一整局切成命名分段（关卡 / Boss / 关键道具），记两套量：**累计时间**（到该分段的用时，与 PB 同点比较出绿/红 delta）和**分段用时**（该段单独耗时，与 gold split 比）。核心概念：

- **PB**：最快的完整一局。
- **Gold split**：某一段的历史最快，不论那局最后如何结束。
- **Sum of Best (SoB)**：所有 gold split 相加 = 理论完美局，几乎总比 PB 快。
- **Possible time save = PB − SoB**：还剩多少时间在桌上。
- 社区原话：「**早期分段丢的时间会一路跟到终点**」——累计 delta 天然是路径依赖的。
- 还有「RNG split 用更宽的阈值」「设 reset threshold 避免情绪化重开」等风险控制习惯，以及按类别（Any% / 100% / glitchless / seed）分开统计。

**一条重要的反面教材**：speedrun.com 有专门文章讲「为什么你的 sum of best 不准」——这一段早触发 0.3 秒，下一段起点就变了、必然慢 0.3 秒，局部最佳相加会系统性高估理论上限。**分段之间存在状态耦合时，不能简单拼接最优片段。**

### 1.4 扑克：决策质量 ≠ 结果质量

虽然扑克有对手，但「把决策与结果分开」的方法论最成熟：

- **judge decisions, not results**（Annie Duke 称 *resulting* / 结果偏见）：+EV 的决定经常输，−EV 的决定经常赢。
- **All-in EV 线**：追踪软件把所有 all-in 的实际结果替换成「当时的期望值」，画一条线；实际线与 EV 线之差就是运气。PokerTracker / Hold'em Manager / GTO Wizard 的 hand review 都这么做。
- **样本量意识**：真实赢率 5 bb/100、SD 90 bb/100 的玩家，打 1 万手仍有约 29% 概率是亏的，10 万手才降到约 4%。单局 / 单月结论基本是噪声。

### 1.5 棋类 AI 复盘（作为对照，不是主参考）

已经收敛到「**确定性引擎判对错，语言层只讲道理**」四层链路：

1. 事实层：SGF / PGN → 引擎逐手产出胜率、目差、候选着法与主变线。
2. 判定层：Chess.com Classification V2 用**期望得分损失**分级（Best 0 / Excellent 0–0.02 / Good 0.02–0.05 / Inaccuracy 0.05–0.10 / Mistake 0.10–0.20 / Blunder 0.20–1.00），且阈值随玩家水平放宽；围棋侧并行用胜率 + 目差 + 吻合度三条曲线。
3. 解释层：GoReflect 的原则是「固定内容全部由程序生成，LLM 仅作下游解释器」——先产出结构化诊断，再加坐标白名单、数字一致性 ±0.05、禁止自行推演等硬校验；配套多 PV 候选与实战着法的具体反驳线。
4. 教学闭环：AI Sensei 的 Quiz Mode 把失误局面存成题，答错更常出现、答对渐隐；Chess.com 的 Retry 强制「先想后看」；跨局侧有 Chess DNA 的九类错误主题。

**只挑关键手**是共识：给业余棋手看 AI 对全部 250 手的意见是灾难，工具价值在于「引擎和大脑之间的过滤器」。已明确的失败模式：给低分段看 12 步引擎变例学不到东西；解释不累积；只给答案不给问题。

### 1.6 享乐型回顾与单人 roguelike

- **Spotify Wrapped / Strava Year in Sport / 主机年度回顾 / Monzo Year in Monzo**：只挑 4–5 个 headline 指标、一屏一个数字、全屏故事卡、正向叙事 + 里程碑、可分享卡片、低用量也正向框定、按参与度给不同视图。**零改进指令**。注意它们的 percentile / top 5% / 社会比较与教育心理学冲突，不能照抄。
- **单人 roguelike run 回顾**：`sts-stat-viewer`（解析 `.run`、12 种可拖拽图表）、`SlayTheSpireData` Run Analyzer（卡牌 / 遗物 / 敌人的选取率与胜率相关、相关热图）、`Spire Vault`（KPI 条、winrate-over-time、一键生成 Share-Run 图卡）、Balatro 的 Deckstats / seeds tracker / Roguelog pro。共同点是 seed / run history 视角、跨局聚合、把随机性当叙事角色，且社区明确警告「只跟 3 个指标，别全量跟踪以免 analysis paralysis」。相关热图不能当因果（有选择偏差）。

## 2. 四条差异，决定什么能抄、什么不能

| # | 差异 | 与棋类 / roguelike 对照 | 直接后果 |
|---|---|---|---|
| 1 | **没有对手** | 棋类是零和 + minimax，V(s) 是「双方最优应对下」的值；我们是单 agent 对抗自然的 MDP | Miss（没抓住对手失误）、对手建模、Great/Brilliant 类标签全部无对应；胜率曲线应换成「达成目标概率 / 期望终局分」 |
| 2 | **状态转移随机** | 落子后局面确定；我们 `P(s′\|s,a)` 是分布 | 结果 = 决策 + 运气；反事实必须**同一随机流配对**（common random numbers），否则差值被噪声淹没；单局 78 个决策点统计功效极低 |
| 3 | **连续分数最大化 + 低容错** | roguelike 是「通关 / 没通关」二元阈值，次优也能过一定难度；高尔夫每杆计入总分但杆间耦合较弱 | 早期误差永久滚进终局；且有**不可逆窗口**（错过 T30 继承 / 合宿 / 剧本机制节点就永久关窗）、资源与阈值非线性。错一个回合可能就错过最高分 |
| 4 | **动机是轻松 + 追分** | 棋类是 mastery / 想提高水平取胜 | 同一份数据要用完全不同的话讲；「应该 / 建议 / 该练」本身就在制造压力 |

**我们比高尔夫还难三点**：状态耦合与不可逆窗口更强；`s′` 是随机实现而非观测位置（所以 `V(after)` 要用期望后验）；参考轨迹必须 like-for-like（同随机流、同配卡、同剧本）。

**一个必须内建的修正**：赛车 / speedrun 基本确定性，所以「丢了 0.3 秒」几乎必然是玩家责任；我们不是。追求极限的玩家最容易自责，报告若把「错过最高分」笼统归因于手法，既不准确又最伤人 —— 理论上限必须和运气实现分栏。

## 3. 教育心理学对语言的约束

| 结论 | 出处 | 约束 |
|---|---|---|
| 反馈分**信息性 / 控制性**；同样一句表扬，加 "just as you should / ought to" 就让自由选择时的坚持度显著下降 | Ryan 1982；Deci & Ryan 认知评价理论 | 「应该 / 建议 / 需要改进 / 该练」不是语气问题，本身损害内在动机；要提供理由并明确可跳过 |
| 反馈把注意力推向「自我」就有害 | Kluger & DeNisi 1996 元分析：607 个效应量、23,663 观测，平均 d≈0.41，但 **38% 的反馈让表现变差** | 不给评级、不贴能力标签、不做社会比较；只讲可观察的这一局。SBI（情境-行为-影响）这类「只讲事实」结构最稳 |
| 评价性情境触发 ego-involvement，即使正面反馈也不再提升内在动机并抬高焦虑 | Ryan 1982 | 「一致率 / 水平 / 弱点 / 你总是…」整体拿掉 |
| 三明治反馈法实证不稳、会稀释信息；空洞表扬（person-directed）无效 | 反馈研究综述 | 用「单点、具体、可行动」；表扬具体动作而非人 |
| 徽章 / 每日任务 / 连续打卡会把玩变成打工 | 过度理由效应 | 不做游戏化任务体系 |

归因上把结果归到**可控、不稳定、具体**的因素（那次体力判断、那次事件选项），归到运气的部分先说清楚，玩家就不必自责。

### 4.3 真正的缺口

1. **实际动作仍是状态差推断**（`metrics_glossary.md:30-39`：先判训练、体力 +25 否证、继承窗口标「继承混合」不参与一致率、`—` 即推断失准），brief §6 自动标「存疑」。
2. **没有逐回合 `regret`**：检查项是 6 条规则命中，`turn_delta` 被当运气分用且明确「不等于属性增量」。
3. **没有累计 delta / 理论可达上限**：`luck_trend.svg` 是运气走势，不是「参考轨迹 vs 实际 + 累计差值」；无 possible time save / constrained optimal。
4. **没有分环节归因**：§1.2 训练画像是按年份 × 训练维，不是按动作类别系统分解漏分点。
5. **没有统计功效**：「存疑」是判据式的；`total_luck_end < -2000` 只是一条经验保守线。
6. **单局、无反事实**：只吃局包，`umaai_next` / `matsuri_base` 的模拟器未接；没有跨局 PB 与自我参照进度。
7. **语域仍偏教练式**：`SKILL.md` description 的「坏手法 / 执行偏离」、六问后固定的「改进建议」段，以及 persona 把 AI 建议人格化为「上级建议」。

### 4.4 现成接缝（改动比想象小）

- **`T(n)` 本身就是参考轨迹的雏形**——已是「局面期望终局分」。不必另造期望线，只需显式命名为参考轨迹，再补「同一随机流下的可达上限」和累计差值。
- **`total_luck_end < -2000`（≈方差量级）已是统计意识**，可升级成置信区间与「不可判定」标注。
- **§2 分段的「阴跌 / 回血 / 账面跳变」措辞，正好是 ramp / step / 假跳**，只需 formalize 成曲线形态判别。
- **`flagged_turns`「按性质归因、不当连续损益读」** 就是「别把程序性波动算进玩家账」。
- **`pitfalls.md:47-50` 的 `turn_delta` 切片边界坑**（按 `turn >= N` 求和会多算一段），与赛车「条件随数据走」、speedrun「分段触发点必须一致」同类，已踩过并记录。
- **`alt_candidate` 的「换了候选 ≠ 不听建议」口径**在接上实测动作后会更有说服力。

### P1｜参考轨迹 + 累计 delta

| 项 | 内容 |
|---|---|
| 目标 | 把 `T(n)` 显式变成参考轨迹，输出「参考 vs 实际」双线与累计差值 |

### P1｜逐回合 regret + 分环节归因

| 项 | 内容 |
|---|---|
| 目标 | 量化「这手相对最优差多少期望分」，并回答「分丢在哪一类动作」 |
| 定义 | `regret_i = E[V(s′)\|s_i,a*] − E[V(s′)\|s_i,a_i]`，**V 必须从该帧 rollout 到终局**，不是当回合属性增量；两侧期望在同一随机流上配对估计（common random numbers） |

| 验收 | 同一局面重复模拟，regret 符号稳定；CI 跨零的回合不被标成失误 |

### P2｜受约束理论上限 + 反事实

| 项 | 内容 |

| 目标 | 回答「这局本来能拿多少」「如果 T42 改选 X 会怎样」 |

> §5.6.2 的逐回合表与 §5.6.4 的三条终局分基准是**两组独立示意**，各自演示一种算法，不要求数值互相对齐。

### 5.6.1 对应 5.0 + P0：原始数据长什么样，实测动作怎么换掉推断

插件已经写好的 `game6309_finalScore.json`（只截 `actions` 附近）：

怎么读：数组顺序就是点击顺序；`turn` 是 0 基（协议 `current_turn − 1`，例如协议里 `43` 写成 `42`）；同一个 `turn` 出现两条，说明「先点了指令、再选了事件第 2 项」。这里没有 `seq` / `requestId`，因为顺序由数组下标给、去重在插件进程内用 RequestId 做完了。

**P0 改的是 brief §6 这一行**。

改进前（靠相邻帧状态差猜动作）：

| 回合 | AI 首选 | 实际动作（推断） | 对应候选 | 标注 |
|---|---|---|---|---|
| T42 | #1 速训练 | 休息？ | — | **存疑**（体力卡 +25 判定线，推断维与建议维相邻） |

改进后（直接读 `actions`）：

| 回合 | AI 首选 | 实际动作 | 对应候选 | 标注 |
|---|---|---|---|---|
| T42 | #1 速训练 101 | 指令 `command_type=3`（回复类） | #3 休息 | 事件另选了第 2 项 |

「对应候选」怎么来的：拿真实的 `command_id` 去当回合候选表比对，命中 #3；事件选择单独记一行。旧的「先判训练、体力 +25 否证、继承窗口标继承混合」整条推断链只在**老局包没有 `actions` 时**作为降级路径保留。

注意「存疑」的变化：以前它表示「动作没猜准」，以后它表示「**这个差值小于模拟噪声，统计上判不了**」——所以标注要保留，只是含义换了（见 §5.6.3）。

### 5.6.2 对应 P1：参考轨迹与累计差值曲线

取 T40–T45 一小段。`R` 是参考轨迹（同随机流、同配卡下引擎给的**局面期望终局分**，就是现有 `T(n)` 的延续），`A` 是实际轨迹。

| 回合 | 参考 R | 实际 A | 本回合 Δ | 累计差值 | 形状 |
|---|---|---|---|---|---|
| T40 | 62,000 | 62,000 | 0 | 0 | 平 |
| T41 | 62,300 | 62,300 | 0 | 0 | 平 |
| T42 | 62,700 | 62,560 | −140 | −140 | **step** |
| T43 | 63,000 | 62,820 | −40 | −180 | ramp 开始 |
| T44 | 63,400 | 63,260 | +40 | −140 | 追回一点 |
| T45 | 63,800 | 63,620 | −40 | −180 | ramp 继续 |

**每个数怎么算的**：

- `本回合 Δ = (A_t − A_{t−1}) − (R_t − R_{t−1})`。例 T42：`(62,560 − 62,300) − (62,700 − 62,300) = 260 − 400 = −140`。
- `累计差值` 就是把 Δ 逐行加起来；终值必须等于 `A − R`，这里 `63,620 − 63,800 = −180` ✓。
- **形状是读出来的，不是算出来的**：T42 一步掉 140 然后持平 = 台阶，有明确地址；T43 之后缓慢继续往下 = 斜坡，说明上游状态（体力 38 没回到位）在持续收赤字；T44 又追回一点、T45 再掉一点 = 锯齿式风格差异，**不标失误**。

报告里不要写「T42 失误 −140」，而是：

> T42 之后曲线有个小台阶，后面几回合又慢慢往下走了一点，主要是那次体力没回到位，不是每一回合都在出错。

**「参考要值得比较」在这里的意思**：如果这份 R 来自别的配卡或别的随机流，那两条线之间的 −180 什么也说明不了（对应赛车「两个都刹早 40 米的人之间是一条漂亮平线」）。所以 `digest.json` 要把 `scenarioId`、配卡、随机流标识、录制年代注记一起存下来。

### 5.6.3 对应 P1：逐回合 regret 与分环节归因

T42 那个局面，引擎重算的候选表（`decisions.csv` 以后要记均值 / 区间，而不是一个点估计）：

| 候选 | 动作 | 从 T42 rollout 到终局的期望分 | 95% 区间 |
|---|---|---|---|
| #1 | 速训练 101 | 68,900 | ±120 |
| #2 | 休息（玩家实际选的） | 68,760 | ±110 |
| #3 | 力训练 102 | 68,700 | ±130 |

**`regret_42` 怎么算**：`E[V|s_42, a*] − E[V|s_42, a_42] = 68,900 − 68,760 = 140`。两个期望必须在**同一组随机流**上各跑 N 次再取均值相减，否则差值会被训练失败、事件之类的噪声淹没。注意 V 是从 T42 一路 rollout 到终局的期望分，**不是当回合五维增量**。

**为什么这 140 不写成「失误」**：差值的不确定度约 `√(120² + 110²) ≈ 163`，而 `140 < 163`，置信区间跨零 → 标「**不可判定**」。对照一下，`#1` 与 `#3` 差 200，不确定度约 `√(120² + 130²) ≈ 177`，`200 > 177` → 那类才够格进「关键回合」。这一步就是 P1 里「阈值改成置信区间」的具体含义。

**逐回合 regret 不能直接相加**：改了 T42 之后 T43 的状态也变了，各回合的边际值会重复计算（和 speedrun 的 sum of best 失真同源）。整局的决策损失要用 §5.6.4 的全局配对模拟得到，不能把 78 个 `regret_i` 求和。

**分环节归因怎么算**（示意结果）：

| 环节 | 归因损失 | 占比 |
|---|---|---|
| 训练选择 | 540 | 46% |
| 休息 / 体力 | 270 | 23% |
| 比赛 / 赛程 | 200 | 17% |
| 事件选项 | 120 | 10% |
| 剧本机制窗口 | 50 | 4% |
| **合计** | **1,180** | 100% |

做法不是把每回合 regret 按 endpoint 求和，而是**消融重跑**：只把「训练选择」这一类动作换成引擎最优、其余保持玩家原样，看全局决策损失少了多少；五类各跑一次，再把 `1,180` 按边际贡献分摊。这样合计必然等于全局值。

这份表最有用的地方是「**意外发现**」：玩家多半以为自己输在事件选项，数据说大头在训练选择——正是 Broadie 用 ShotLink 发现「业余选手真正漏分在 125–175 码 approach，而不是推杆」的同一个效应。

### 5.6.4 对应 P2：三条终局分基准、理论上限与反事实

用扑克「实际线 vs EV 线」的框架，把整局拆成三个数（各自都是**重跑多次的均值**，不是单局一次抽样）：

| 记号 | 含义 | 示意值 |
|---|---|---|
| `O` | 受约束最优线：本局信息下，引擎按最优策略从头走到尾的期望终局分 | 70,160 |
| `E` | 决策线：本局信息下，**玩家实际这套动作序列**重跑的期望终局分 | 68,980 |
| `A` | 实际终局分（真机一次抽样） | 68,420 |

**怎么算 / 怎么分解**：

- `决策损失 = O − E = 70,160 − 68,980 = 1,180`，正好等于 §5.6.3 消融表的合计 ✓
- `运气贡献 = A − E = 68,420 − 68,980 = −560`
- `总差距 = O − A = 1,740 = 1,180 + 560` ✓

**`O` 为什么叫「受约束」**：它是同一随机流、同一配卡、且体力 / 技能点预算与剧本机制不可逆窗口都成立的前提下跑出来的完整最优策略；**不是**把 78 个回合各自的最佳片段拼起来。所以「这局上限 70,160」是可信的，「各回合最佳相加 71,xxx」是假的。

**反事实分支长这样**（「如果 T42 改选 #1 速训练」）：

> 同一随机流下从 T42 接 #1：T43 体力 38→22、速度 +32、羁绊 +2；T44 得补一次休息；到 T47 期望终局分比实际路线高约 **95 分**。

注意 95 小于 §5.6.3 里 T42 单点的 140 —— 因为后续要补一次休息，机会成本吃掉了一部分。这个差额就是「不能拼接局部最优」最直观的演示。

**报告话术**（三栏分开，避免把运气说成手法）：

> 这局 68,420。按同样的运气重跑，你这套走法大概 68,980；如果每一步都按当时算出来的最优走，约 70,160。差出来的 1,740 里，约 1,180 是路线选择，约 560 是这局运气没站你这边。

### 5.6.5 对应 P2：默认轻量层与跨局自我参照

`report.html` 默认只给三句，30 秒读完：

> 这局 68,420，前期稳，T54 那次继承把速度上限抬了 24 点，是全程最亮的一手。
> 运气这回没太站你这边，比平均多失败了 2 次训练，差不多白丢 560 分。
> T42 前后还有一条练速的路，好奇的话可以点开看看。

折叠层给三个入口：「展开完整数据」「这一局的 78 个回合」「和上 5 局比一比」。硬数据一键可达，但默认不摊开。正向先行、结尾落在「下一局值得期待的东西」，不以失分清单收尾。

**跨局只跟自己比**（不做百分位 / 排名）：

> 同样是体力 40 以下的岔路口，上 5 局出现 12 次，这局 2 次。

这句话里没有「你的弱点」「水平」「评级」，只有一个可观察的事实和一次自我参照 —— 对应 §3 里 Kluger & DeNisi「反馈指向任务而不是自我」的约束。

### 5.6.6 一张表看懂五个阶段各自多做了什么

### 6.2 改写示例

| 原句 | 改写 |

| 执行偏离：T42 选了休息，AI 建议速度（存疑） | T42 你先稳了一手。当时体力 38，另一条路是练速——两条差得不大，后面两次训练失败影响更大 |

| 本局失误 TOP5 | 这局最值得回看的几个岔路口 |
| 主要失分点 | 最值得记住的是 T54 那次继承，速度上限 +24 |

### 6.3 persona 微调（只改表达，不动数据与流程）

`persona.md` 把 `ai_choice` 统一改成理事长第一人称「我当时的建议」，玩家是「部下训练师」。人设贴游戏且讨喜，但把 AI 建议人格化为**上级建议**会让「没采纳」带上对权威的偏离感。建议：

- 「我当时的建议是速训练」→「当时算出来还有一条练速的路」
- 「你改成了…」→「这局走的是…」
- 「改进建议」段标成**可选、可不看**；去掉「下一局不妨…」的义务感
- 保留亲切、感叹号、猫的梗、夸到具体回合与数字

### 6.4 别抄清单

- 别把「胜率跌 20% = 大恶手」搬过来（多目标、随机、非平稳）。
- 别给「12 步长变例」，给 1 条具体指令 + 1 个可选尝试。
- 别让 LLM 裸判局面（棋类已有编造不存在棋子的公开翻车案例）；坚持 `digest.json` 事实层 + 叙事层只读事实。
- 别只看终局评分不看运气（对应围棋「只看胜率不看目差」）。
- 别把某回合没有 `actions` 当成玩家没操作（中途加载会缺，已写入契约）。
- 别用三明治、空洞表扬、徽章 / 打卡、跨局「你的弱点」标签、百分位 / 排名。
- 减压 ≠ 藏数据：硬事实必须一键可达。
- 别把 sawtooth（风格差异）当失误；别用不一致当评分。
- 别用引擎绝对最优当基准压轻松玩家（用同配卡 / 同水平相对基准，高尔夫按差点分层同理）。

## 7. 风险与边界

1. **统计功效**：单局 78 个决策点，单局「好手法 / 坏手法」结论几乎必然是噪声；跨局聚合才算手法。扑克的类比：5 bb/100、SD 90 的真实赢家打 1 万手仍约 29% 概率落后。
2. **随机流一致性**：反事实 / regret 若不在同一随机序列上配对，差值无意义；参考轨迹若不同配卡 / 剧本，整条 delta 失效。
3. **不可逆窗口**：马娘的窗口与资源约束比赛道分段强，理论上限必须受约束，不能拼接局部最优。
4. **结果偏见**：追求极限的玩家最易自责；「错过最高分」要拆成决策与运气两栏。
5. **范围约束**：本轮不改 `umaai_next` / matsuri 系库；消费端白名单与分流由用户在各自重构中吸收（handoff §7.4）。在此之前终局帧不进 AI 引擎、也不进局包归档链路，验证以插件目录 JSON 为准。
6. **插件依赖闭包**：`SendGameStatusPlugin.zip` 不含依赖 DLL，重打时必须连同 EventLogger / Festa / Ramen / Legend / Pioneer 五个包成套同步（handoff §7.3）。
7. **数据来源**：本方案的领域类比是方法论参考， poker / golf 的效果数字来自各自领域，不能直接当我们的指标；围棋侧「提升棋力」多为厂商口径，无大样本对照。

## 附录 A：术语对照

| 外部术语 | 我们的对应 |
|---|---|
| 期望剩余杆数 `V(位置)` | 局面期望终局分 `T(n)` |
| `SG = V(before) − V(after) − 1` | `regret` 的价值差分形式（但 `after` 用期望后验） |
| SG 四类分解 | 训练 / 休息 / 比赛 / 事件 / 剧本机制分环节归因 |
| delta time trace | 参考轨迹 vs 实际的累计差值曲线 |
| step / ramp / sawtooth | 单回合失误 / 上游状态拖累 / 风格差异（不算错） |
| theoretical best lap | 同一随机流下的受约束可达上限 |
| possible time save | 「还剩多少分在桌上」 |
| gold split / sum of best | **不要照搬**（状态耦合会失真） |
| all-in EV 线 | 期望轨迹；实际线与期望线之差 = 运气 |
| 记分卡 vs 技能分 | 实际终局分 vs 运气中性下的期望终局分 |
| 差点分层基准 | 同配卡 / 同水平玩家相对基准 |
| PB / handicap | 跨局自我参照，**不做社会比较** |
