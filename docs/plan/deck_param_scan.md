## 1. 背景与目标

#48 实测（seeds 82000–84999，3000 局/档）耐 / 根 / 智主卡组比默认速主档低
3.9k–4.6k，失分集中在速度分项；现有 [`benchmark/decks/measured.csv`](../../benchmark/decks/measured.csv)
是在默认（速主）参数下、单槽贪婪 `topk=6`、单种子块跑出来的，只能作为定卡起点。

本轮目标：

1. 四套 build 各锁定一套主卡组（+ 一套影子卡组），作为参数扫描的固定夹具；
2. speed 21101 允许换成更强的卡组；若确认显著，替换默认卡组并重录基准；
3. 用单卡控制变量 + 按类型排名的方式定卡，不设绝对分数线；
4. 卡组锁定后，按 `fusion → advice → status_weights → 其余手写旋钮` 扫描，
   全部用配对 Δ 排序 + 独立块复现判定。

## 3. 定卡：固定 5 个位置，只换 1 个

### 3.1 单卡控制变量

以当前基准卡组为 `base`。每次固定其余 5 个位置（4 张训练卡 + 友人），只换第 6 个位置：

1. 第 i 个训练位，候选 = 该类型全部可进池卡；同角色与固定卡冲突的剔除。
2. 生成卡组 CSV：第一行 `base`，后面每行 = `base` 只替换第 i 槽；同 comp、同友人。
3. 一次 `cardtest run` 跑完全部候选，同一种子块、`--correct holm`，得到每个候选相对
   `base` 的配对 Δ 与 CI95。
4. 按 Δ 从高到低排序；只有 Δ>0 且 CI 不跨零才替换。
5. 5 个槽依次过一遍；只要有一槽发生替换，就用新卡组再跑一轮；最多两轮。

对 2 张同类型的 build（2 速 / 2 耐 / 2 智），两个槽位分别独立排名：排槽 0 时固定槽 1，
排槽 1 时固定槽 0，不能假设两个槽对称。只有两槽前二在 CI 内打平时，才做一次
`top2 × top2` 的联合确认；其余情况不做多槽枚举，保持控制变量。

### 3.2 类型排名表

「按类型从高到低」限定在同一 build、同一槽位、同一 `base`、同一批种子下，比的是
**配对 Δ**，不是绝对分；不跨类型、不跨 build 直接比较。

每张表至少给：

| rank | card | Δ vs base | CI95 | W/L/T | tier | panel 分（参考） |
|---|---|---|---|---|---|---|
| 1 | 30317 待兼诗歌剧 | +210 | ±140 | 1563/1437/0 | A | 135.0 |
| 2 | 30311 乐透心 | +40 | ±150 | … | B | 110.0 |

- CI 跨零的卡归入「与 base 不可分辨」层；CI 重叠的卡视为同一 tier。
- 输出两层：按槽位的完整排名（定卡直接使用）；按类型汇总的高→低表（注明槽位与 base）。
- 排名是条件性的：换 `base` 或换参数后要重排。第一轮按当前默认参数排；参数定档后
  再做一次稳定性复排。

### 3.3 确认与采用

- 一轮结束后，最终卡组 vs 起始卡组，换独立种子块（86000–86999）、20k 局确认。
- 确认 CI 不跨零才写入 `benchmark/decks/<build>.csv`；否则保留起始卡组，排名表照常保留。
- 影子卡组（panel 档或 measured 次优套）不参与调参，只用于参数迁移验证。

### 3.4 speed 与重录基准

- speed 21101 跑同一套单卡流程，基准 = 当前默认卡组。
- 若新卡组在确认块上显著优于当前默认：
  1. 更新 `data/ai_config.toml` 的 `[sim].cards`，同步 `benchmark/decks/measured.csv` 的默认行；
  2. 用同一 73200 块重录 `benchmark/baselines/a-normal.json` / `b-ideal.json` 的手写 100 局与
     搜索 10 局，量化换卡位移；另用 93000 块做独立复核；
  3. 更新 README / handoff / changelog 的基线表，重跑 seed 61444 冒烟；
  4. 卡组是全局 `[sim]` 输入，a-normal 与 b-ideal 两条都要重录。
- 若确认不显著，保留当前默认卡组，只记录排名。
- 换默认卡组先只重录基准、不动参数；默认档参数是否重扫另开一轮，避免「换卡 + 换参」混在一起。

### 3.5 预算

单 build 一轮：5 槽 × 每类型 50–70 张 × 5000 局 ≈ 1.5M 局，24 线程约 2 分钟；
两轮约 4 分钟。四套合计约 15–20 分钟（含确认块）。

## 4. 参数扫描

### 4.1 变体与批量跑测

扫参脚本生成一份完整配置：原 `[decks.default]` + 生产档 + 若干 `[decks.<variant>]`
（`variant = true`，只写差异；variant 继承 default，生成器要把生产档相对 default 的
完整差异一起展开）。再生成一张 decks CSV，行名 = variant 名，卡组列都填该 build 的主卡组：

```bash
cardtest run --decks benchmark/_local/scan/candidates.csv \
  --matsuri-config benchmark/_local/scan/scan.toml \
  --ref ref_stamina --games 5000 --seed 87000 --threads 24 \
  --correct holm --out benchmark/_local/scan/result.csv
```

- `ref_<build>` 行名不命中任何档，按 comp 自动回落到该 build 的生产档，作为参照臂；
- 每批 ≤120 个变体，控制输出与内存；
- 同批所有变体用同一批种子，直接读 `cardtest run` 的配对 Δ / CI / W-L-T。

### 4.2 扫描顺序

| 阶段 | 参数 | 方式 |
|---|---|---|
| 0 | 默认参数 | 10k 局基线，报五维 / 演目 / 决策分布 |
| 1 | `fusion` | 合法配对全枚举（year2 2 组 × year3 3 组，共 120 种），5000 局/种 |
| 2 | `advice` 六窗口 | 固定其余窗口，逐窗口枚举 120 排列，两轮 |
| 3 | `status_weights` | 5 维坐标粗扫（默认 ±50% + 终局目标反推点）+ 局部细化 |
| 4 | `rest_vital` / `weights.vital` / `vital_decay` / `vital_idle` | 单旋钮网格 |
| 5 | `overflow` / `endgame` / `dynamic` / `pt_favor_rate` / `act_level_target` / `friend_outing_early` / `self_race` | 单旋钮 + 小组合 |
| 6 | 联合精修 | 坐标 + 小规模 UCB，只在前 20 组上 |
| 7 | 留出确认 | 主卡组 + 影子卡组，20k 局 |

`fusion` 与 `advice` 强耦合（801 硬约束、401 落位）：扫完 `fusion` 后 `advice` 要跟着重扫一轮。

### 4.3 判定

- 每阶段按配对 Δ 排序，前 5 组换独立块（90000–90999）复核；
- 只有复核方向一致、且在影子卡组上同向，才写进 `[decks.<build>]`；
- 不设固定 +N 分门槛；判定口径是「独立块 CI 不跨零 + 影子卡组同向」；
- 默认档逐位不变：seed 61444 冒烟仍为 86053 / PT 11864，直到 speed 换卡被正式采用。

## 10. GA 联合调参（2026-11-08 ～ 11-09）

§9.4 第三条（五维 → 其余旋钮 → 联合精修）改由 CMA-ES 一次联合搜完；stamina 以 §2.1 起始卡组 +
§9.1 槽 2 替换重建夹具 `benchmark/decks/stamina_build.csv` 后重新入档。

### 10.1 方法

- **搜索**：`scripts/ga_trainer.py search`。74 维 = 39 个训练员旋钮（含 `pt_favor_rate` 与两个布尔）
  + 融合 5 个随机键 + 6 个教诲窗口各 5 个随机键；λ=48、σ₀=0.1；手写档（`search_n=0`）。
- **场景**：马娘 105902 / 102102 / 100101 × 种马 4 套（蓝 18 速 / 9 速 9 耐 × 根因子有 / 无），
  每候选每场景 250 局，同代同种子（CRN）。
- **适应度**：场景均分 − 100000 ×（1 − 友人出行走满 5 段的局占比）。友人走满是硬需求。
- **门禁**（看结果前固定）：只认复核分最高者；验收块上对现值、对起点都 z > 2.58；
  走满率 ≥ max(现值, 起点) − 0.002；影子卡组对两者 Δ 均 > 0。
- **搜索档验收**：`scripts/search_check.py`，N=8192（线上默认）、同种子同场景配对。
  马娘轮转 105902 / 102102 / 100101 / 112901 / 114101 / 106301（卡组含本人卡的剔除，智卡组去 106301），
  × 主 / 影子卡组 × 4 套种马。规则（看结果前固定）：t ≥ 1.96 落库；0 < t < 1.96 补局一次后以全部对数定；
  t ≤ 0 不落。
