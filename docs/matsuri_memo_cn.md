## 1. 剧本骨架

### 1.1 回合与结算点（`data`）

| 项              | 值                                                                          |
| -------------- | -------------------------------------------------------------------------- |
| 回合范围           | `turn 0` – `77`（共 78 回合）                                                   |
| 进度汇报会 / 本番     | turn **23 / 47 / 67**（原始 24 / 48 / 68）                                     |
| 门槛（全 5 演目均需达到） | Lv **≥3 / ≥5 / ≥6**（`need_act_num = 5`）                                    |
| 年末统一结算         | turn **23 / 47 结束**时：剧本结算 → 年底事件 → 训练Lv 提升 →（47 **大成功**时）**新 NPC 加入 +5 人** |
| 骏大祭合宿窗口        | turn **12–15 / 36–39 / 60–63**（原始 13–16 / 37–40 / 61–64）                   |
| 教诲可调整窗口        | turn **2 / 11 / 23 / 35 / 47 / 59**（原始 3 / 12 / 24 / 36 / 48 / 60）         |
| URA 收尾         | turn 68–77，本番后剧情结束但仍可攒槽 / 排练                                               |

> **回合 ↔ 月份（由三个锚点反推，自洽）**：turn 0 = 1 年目 1 月前半；turn 11 = 6 月后半；turn 12–15 = **合宿＝7 月前半 / 7 月后半 / 8 月前半 / 8 月后半**；turn 23 = 12 月后半（Junior 汇报会）；turn 67 = 3 年目 10 月后半（本番）。
> ⇒ 「8 月后半结束」写成回合号就是 **turn 15 / 39 / 63 结束时**（Junior / Classic / Senior 各减 24）。同一年内的月份位移固定为 1 回合 = 半个月。

### 1.2 目标结构（`memo`）

- 各马娘**固有目标赛事** + **年末进度汇报会**（Junior / Classic）+ **Senior 10 月后半本番**。
- 本番（turn 67）是剧本最终结算，**不是育成结束**；之后仍打 URA 决赛到 turn 77。

### 1.3 核心循环

```
演目 → 演目负责人 → 教诲（传授 / 改派 / 转成）→ 演目排练 → 进度汇报会（永久加成）
```

节奏上的三个「产出源」：**排练拿演目Lv**、**汇报会拿永久加成**、**比赛 / 休息拿演目槽**。

### 2.2 担当编排（演目负责人的分配）

> **一句话流程：link 钉位 → 卡按类型进本位 → 满位就沿固定链改道 → NPC 每演目 1 人兜底 → 带吾妻再补 1 人。**  
> 前三步决定「5 张支援卡各自坐哪」，后两步决定「编组外 NPC 怎么填」。  
> **顺序不可交换**——先钉 link 会改变后续所有位的空余名额，先补 NPC 就分不清「谁占了几张卡」。

**谁参与这条流水线**

| 对象               | 参与卡片落位               | 占「整位 2 张」名额 | 参与 NPC 基数             |
| ---------------- | -------------------- | ----------- | --------------------- |
| 5～6 张普通支援卡（含 link；不带吾妻时最多 6） | ✓                    | ✓           | —                     |
| 编组外神驹 NPC        | —                    | —           | ✓（每演目 1 人）            |
| 吾妻（友人卡）          | ✗                    | **✗**       | ✗（但**带她时 NPC 总数 +1**） |
| 育成马娘             | ✗（统括 5 人的「神司驹」，不是担当） | ✗           | ✗                     |

> **两个「占位」要分清**：吾妻**占编成的 1 个卡位**（所以带她时普通支援卡只能 **5 张**），
> 但**不占训练位的 2 张卡配额**（所以她不挤掉任何人）。⇒ 编成卡数 = **带吾妻 5 张 / 不带 6 张**（U38 的 6 卡编成由此而来）。

**五步流程（可直接照此实现）**

```
① link 卡：钉到各自的固定演目（不看卡类型），各占该位 1 个名额
② 其余普通卡：进自己类型对应的训练位；该位已有 2 张卡则跳过
③ 仍未落位的卡：按「外派链」改道，遇满位继续跳
④ NPC 基数：5 名神驹，每演目 1 人
⑤ NPC 余额：带吾妻时多 1 人，给「卡 ＋ NPC 人数最少」的演目，并列按 速→耐→力→毅力→智
```

**三条可直接对账的算例**

| 卡组              | 落位（速/耐/力/毅/智）               | 各步实际动作                                                      |
| --------------- | --------------------------- | ----------------------------------------------------------- |
| 5 张速度卡（无 link）  | 速 2 / 毅 2 / 耐 1             | ② 流镝马收满 2 → ③ 溢出 3 张：毅力收 2、耐力收 1                            |
| 智大和 ＋ 3 速 ＋ 2 毅 | 速 2 / 耐 2 / 毅 2             | ① 大和钉流镝马并占掉 1 个名额 → ② 流镝马再收 1 速、大曳收 2 毅 → ③ 余 2 速：毅力已满，落到耐力 |
| 21101 ＋ 吾妻      | 速 2 / 耐 1 / 力 1 / 毅 0 / 智 1 | ② 五张全部本位（无溢出）→ ④ 各 1 人 → ⑤ 第 6 人给卡数最少的大曳                    |

- 第 2、3 行是 `user` 2026-10-30 的真机算例；第 1 行为同规则推演（落位已确认）。
- 三行都满足 **①～⑤ 走一遍就能复现**，可作为落位算法的回归用例。

**(a) 支援卡：谁能进哪个位**

**① 默认落位**：卡类型 → 对应训练位（§2.1 表）。

**② 例外：link 卡钉死固定演目**，不看卡类型（`memo`：`演目担当固定`）。  
多张 link 时**先各自钉位**，再按类型落其余卡（`memo`：`シナリオリンク+2枚以上ならシナリオリンクが優先`）。

**③ 容量：每个训练位总共 2 张卡，不分属性。**

- 本属性卡、外派进来的别属性卡、link 卡**一律各占 1 个名额**；**吾妻不占**（§11.2）。
- 所以「这个位还能不能收卡」只看**已站几张卡**，不看类型。
- **实现口径（2026-10-30）**：这条「每训练位总共 2 张卡」**只在担当分配时成立**；进入每回合训练人头分布后
  不受该限制，只受**每训练位最多 5 人（含 NPC）**约束。
- **判定依据**（`user` 2026-10-30 实测）：**智大和 ＋ 3 速 ＋ 2 毅** → 大曳已有 2 张毅力卡，  
  **一张速度卡都没收**。若按「每属性各 2 张」，大曳本该再收 2 张速度卡（共 4 张），实际没有  
  ⇒ 容量是**整位 2 张**，不是「每属性 2 张」。
- 卡不能「不登场」：每张支援卡都必须落到某个演目，没有待命状态。  
  但座位总量很宽松（5 演目 × 5 座 = 25 座，编成 5 卡 ＋ 5～6 名 NPC = 10～11 人），  
  **限制落在「每位的 2 张卡」这条配额上，不是坐不下**。

**④ 外派链（按卡类型查表，遇满位跳过）**

| 卡的属性 | 外派去向（批次顺序）    |
| ---- | ------------- |
| 速度   | 毅力 ×2 → 耐力 ×2 |
| 耐力   | 速度 ×2 → 毅力 ×2 |
| 力量   | 智力 ×2 → 速度 ×2 |
| 毅力   | 力量 ×2 → 智力 ×2 |
| 智力   | 耐力 ×2 → 力量 ×2 |

- 表里的「×2」是**该批次的接收上限**，不是目标位的容量；目标位实收几张仍受 ③ 的「整位 2 张」约束。
- **遇满位就跳过，不绕去空位**：同一算例里纳舞、飞悬都空着，速度溢出却越过满员的大曳落到耐力，  
  没有去「人最少」的位置。落位由**固定链**决定，不做动态平衡。
- **最多走两跳**：5 张卡外派 3 张（毅力 2 ＋ 耐力 1），6 张卡外派 4 张（毅力 2 ＋ 耐力 2）；`耐力 → 力量` 那一跳永远用不到。

**⑤ 对账：`memo` 的例句**  
`賢さダスカ＋スピ5なら、ダスカ＋スピ1枚がスピード、残りは根性2スタミナ1`

- **编成是合法的**（`user` 2026-10-30）：**不带吾妻时支援卡可以有 6 张**（吾妻只占「友人位」、不占卡配额），
  所以 **1 张賢さ大和 ＋ 5 张速度卡 = 6 张**。
- 前两句**正确**：大和钉流镝马并占掉 1 个名额 → 速度卡只能再进 1 张（**大和 ＋ 1 速 = 速度位 2 张，满**）。
- **6 张卡时**：大和 ＋ 1 速 占满速度位 → 剩 4 张速度卡沿链外派 **毅力 2 ＋ 耐力 2**
  ⇒ **速 2 / 毅 2 / 耐 2**（正好占满 3 个演目、6 个卡位）。（`user` 2026-10-30 确认，U38 ✓）
- `memo` 例句里的「根性2スタミナ1」对应的是 **5 张卡**的编成（智大和 ＋ 4 速 ＋ 吾妻），与上表同一套规则。
- 结构上和「纯 5 速 = 2 / 2 / 1」一致：**link 顶掉 1 个名额**，速度侧从「2 张速度卡」变成「大和 ＋ 1 张速度卡」，
  多出来的那 1 张沿链继续外派。

**⑥ 两种代价（对称的两头）**

| 情形                         | 机制          | 损失                                                                                              |
| -------------------------- | ----------- | ----------------------------------------------------------------------------------------------- |
| **link 卡类型不一致**（智力大和钉在速度位） | 被钉在不属于它的训练位 | ① 本职训练位少 1 人 → 友情密度↓ ② 槽只涨**他自己担当**的演目（不是脚下的训练位，U30 ✓）→ 速度位少一人推流镝马槽 ③ 该演目的教诲少 1 个触发源 ④ 吃掉落位位 1 个卡片名额 → 本类型卡**提前一档外派**（第 2 张起而非第 3 张） |
| **卡被外派**（速度卡落到耐力位）         | 成了外来户       | ① 自身加成落在错位 ② 被推开的演目**缺卡侧加成**（友情 / 训练效果 / 获得量 / 得意率全为 0）——但**槽照涨**（该位仍有 NPC，约 +1/回合）             |

- link 的**唯一正面收益**是那张金技能（§11.3）。类型一致时「固定」只是复述默认结果，**零增量**；  
  所以带 link 卡应优先选与固定演目**同类型**的那张，不同类型时要按「一个金技能换一个主力训练位」取舍。
- 外派只让节奏**变慢变薄**，不是停摆：零卡位约 +1 槽/回合，2 卡位（3 人物）约 +3 槽/回合。  
  是否拖垮汇报会（Junior Lv3 / Classic Lv5）与本番（Lv6）门槛，取决于该位被点到的频率，需实测。
- 推断：配额设为 2 应是「保证每个演目都有担当能推槽」的设计；`memo` 未给意图，此为读法。

**(b) 编组外 NPC**

**① 两批，各自独立**

| 批次    | 数量                   | 时点              | 备注                                                                       |
| ----- | -------------------- | --------------- | ------------------------------------------------------------------------ |
| 第 1 批 | **5 名**（带吾妻 **6 名**） | turn 2          | 数量**只由带不带吾妻决定，与卡片分布无关**                                                  |
| 第 2 批 | **固定 +5 名**          | turn 47 结束的统一结算 | **每演目 +1 的平铺发放**，**不再走余额层**；带不带吾妻都是 +5（开局已配平，见 (c)）；**大成功时**发放，非大成功见 U27 |

**② 摊法（两层，只对第 1 批适用）**

1. **基数层**：5 名神驹**各占 1 个演目** → 每演目 1 人。
2. **余额层**：带吾妻时的第 6 名投给「**卡 ＋ NPC 人数最少**」的训练位；并列按 §2.3 属性序（速 → 耐 → 力 → 毅力 → 智），见 U32。

- **不存在「补到 ≥2 人物」这条规则**：零支援卡的位**常态就是 1 人物**，槽照常 +1/回合（§2.3）。
- 实测（`user` 2026-10-30）：① **6 张普通卡、不带吾妻** → 5 名，每位置各 1 名，纳舞 / 飞悬只有 1 人物；  
  ② **21101 ＋ 吾妻** → 6 名，第 6 名落在大曳（该局唯一 0 卡位）。两者都是**单回合快照**（站位随机，见 ④），
  只作旁证，规则以上面的两层口径为准。

**③ 不与编组卡 / 育成马娘同角色**

- 某神驹的 `chara_id` 若已在编组里（当作支援卡），或**正是当前育成马娘** → 换成**随机非 link 角色**（`memo` / `user`）。
- **只换角色、不改人数**（仍 5 / 6 人），也不改变上面的两层摊法；**每个演目仍恰好 1 名 NPC**（`user` 2026-10-30 确认，育成马娘那一路也如此）。

**④ 担当 ≠ 站位（两层，最容易混）**

| 层         | 内容                | 是否随机          |
| --------- | ----------------- | ------------- |
| **担当**    | 谁是哪个演目的负责人（上面那两层） | **不随机**，按规则算定 |
| **每回合站位** | 这一回合实际站在哪个训练位     | **均匀随机**      |

- NPC **没有得意率** ⇒ `distribute_all` 里 5 个训练位**等权随机**。  
  判定顺序沿用通用实现：**① 先判「不在」**（`absent_weight`，取值见 U29）→ **② 出场则等权随机**；  
  「不在」的判定**不含得意率**。
- ⇒ **每训练位的 NPC 期望人数恒为 1**（带吾妻 1.2），**与卡片怎么偏科无关**。  
  所以偏科不影响槽的**期望**增长，只损失卡侧加成；单回合才有方差（某位 0 人或 2 人）。  
  规划用期望值，单局复盘按实际站位算。
- **只有演目亮起（槽满）时**，NPC 才被钉在该演目对应的训练位上（§3.1）。
- **所有亮起位置都锁人（2026-10-31）**：亮起演目的担当 NPC / 卡**必定出现、锁定担当位、不判不在率**；
  只有**分身**和**未亮位置**的担当可以移动。**亮起过多会减少其他位置的期望人头**，所以是否亮起 /
  何时执行有策略性。
- **实现口径**：**担当分配是剧本开始 / NPC 加入时的一次性动作，不是回合阶段**；
  **每回合的 `distribute_all` 才是阶段**。普通训练位卡与 NPC 都走基础库算法（卡含剧本得意率加成、
  NPC 无得意率）；**所有亮起演目的担当卡 / NPC 锁定担当位、不判不在率**，未亮位置仍自由站位并计算不在率。

**(c) 追加负责人**

| 触发                                       | 追加量                             | 来源                                                                         |
| ---------------------------------------- | ------------------------------- | -------------------------------------------------------------------------- |
| **turn 47 结束**的统一结算里，**Classic 汇报会大成功**时 | 每演目 **+1 人**，合计 **+5**（25 → 30） | `user` 2026-10-30；`frame*` 旁证 `evaluation_info_array` 25 → 30 条（5×5 → 5×6） |

- **时点是「第二年末回合 47 结束」，不是「Senior 期开始」**：这一次结算统一处理  
  **剧本结算 → 年底事件 → 训练Lv 提升（大成功）→ 新 NPC 加入（+5 人，大成功）**，四项绑在同一个结算点。
- **固定 +5，带吾妻也不补第 6 名**（`user` 2026-10-30，U35 ✓）：  
  第 1 批带吾妻之所以是 6，是因为**开局要配平**（每演目 1 人 ＋ 吾妻那 1 人补最少位）；  
  第 2 批是在**已配平的 25 人**上做「每演目 +1」，**各演目同时 +1 后仍然配平**，  
  没有「缺人的位」可用，所以恒为 **+5**——不再有余额层。
- **条件是「大成功」**，与 `memo` 的「Classic 12 月大成功时各演目 +1 人」一致。  
  **非大成功时是否仍 +5 人 —— 待查（U27）**；实现上先建「大成功才加」的分支。
- 加的是**人数上限**（每演目 5 → 6），不是新增演目；总人头 25 → 30。

前提：参与分配的是 **5～6 张普通支援卡**（不带吾妻时 **6 张**；吾妻**不参与、不占配额**，§11.2）；

### 2.3 演目槽（gauge）

| 项               | 规则                                                                                                | 来源                |
| --------------- | ------------------------------------------------------------------------------------------------- | ----------------- |
| 上限              | **5**（`need_act_gauge = 5`，全期恒定）                                                                  | `data` / `frame*` |
| 自然衰减            | **无**，不会随回合减少、不会过期                                                                                | `help` / `user`   |
| 排练回合            | **选了排练就没有训练这个加槽来源** ⇒ 该回合 5 个演目的槽都不涨（不只被排的那个）；被排的演目执行后**清零**，其余 4 个维持原值。**若这回合选的是普通训练，则按下一行正常涨槽** | `user` 2026-10-30 |
| 训练 | 参与该次训练的担当，**每人给自己担当的演目 +1**（按担当归集，不按训练位，U30 ✓）；**闪彩（友情）的担当 +2**，同场其他担当仍 +1 | `memo` / `user` |
| 生涯（目标）比赛        | **+4**（已定 2026-10-31）；按 **4 次 +1** 入账，落点 **演目 Lv 低→高**，同级按 速→耐→力→毅力→智，满槽跳过 | `user`   |
| 休息 / 外出 / 非生涯比赛 | 只加**一个**演目（落点见下行），**+1**（已定）                                                                      | `user` 2026-10-30 |
| 事件              | 可直接加槽，**受上限拦截**（`not_up_parameter_info.is_overflow_act_gauge_event_gain`）                         | `frame*`          |
| 分配顺序            | **① 演目Lv 最低 → ② 槽最低 → ③ 仍相同则按「速 / 耐 / 力 / 毅力 / 智」的顺序**                                            | `user` 2026-10-30 |

- **「排练回合不涨槽」是「按行动」算的，不是「按回合冻结」**（`user` 2026-10-30 澄清）：  
  排练本身就是这回合的训练行动，选了它就**没有「训练」这一加槽来源**，所以 5 个演目一律不涨；  
  **同一回合改选普通训练，就按「训练」一行的规则照常涨**（比赛 / 休息 / 外出的加槽也各按自己那行）。  
  换句话说这条只在「本回合的动作 = 演目排练」时生效，不是「进入某个回合后全场停涨」。
- **已定（`user` 2026-10-30）**：「友情 +2」只给**闪彩（彩圈）的那名担当**，同一次训练里其他参与担当仍按 +1 计。  
  换言之 +2 是**个人属性**，不是整场训练的档位；一次友情训练里有 3 名担当参与（1 名闪彩 + 2 名普通），  
  该演目槽实得 `2 + 1 + 1 = 4`。
- **一步满槽的两种组合**（`user` 2026-10-30）：**2 名闪彩**（`2 × 2 = 4`）再补 1 点即到 5——
  - 2 闪彩 ＋ 该训练位上**恰好站着一名本演目的担当 NPC**（+1）——要「**本演目的**担当」才算；
    随便一名 NPC 站在那儿，只推**他自己**演目的槽（U30 ✓）；
  - 2 闪彩 ＋ **研钻教诲的追加排练**（+1）。  
    这是「槽满 → 该训练位变演目排练」的最快路径。注意 NPC 的落位是**随机**的（§2.2(b)），  
    所以「2 闪彩 + NPC 同框」只能**就现场所见**利用，不能预先安排；可安排的是「2 闪彩 + 追加排练」。
- 休息 / 外出 / 非生涯比赛的**落点与增量均已定**：只加 **1 个**演目，落点按「Lv 最低 → 槽最低 → 属性序」，量 **+1**。  
  复核可用 `command_gain_act_gauge_array`（命令类型 3/4/7/8）读前后差值。
- **生涯（目标）比赛的增量待查**（`memo` 记 **+4**，见 U31）。若成立，一场目标赛 ≈ 4 点槽，  
  是排练之外最快的槽来源，也是「靠比赛喂槽」这一打法的数值基础。
- **槽满 → 该训练位变成演目排练**；**亮起期间该位置不能做普通训练**（`memo` 本轮新增）。
- **「参与人数」在普通训练里不可预排**：NPC 落位随机（§2.2(b)），同一回合同一个训练位上站着谁要看现场；
  排练则不同——该演目担当全员登场（§3.1），人数可算。
- **排练时，NPC 站到「非其担当演目」的训练位：一个槽都不涨**（已定，`user` 2026-10-30）——
  既不涨他脚下那个正在排练的演目，也**不涨它自己的担当演目**。与「排练回合不涨槽」同向，
  等于确认排练回合**没有「靠外来 NPC 补 1 点槽」这种漏算**；这类同框 NPC 也不计入排练的**加槽人数**。
  （面板 / 教诲人数是否把这类同框 NPC 算进去，本文档未单独确认；§3.3 现按「NPC 只计人头」处理。）
- **加槽按「人物所属担当」归集，不按脚下的训练位**（已定，`user` 2026-10-30，U30 ✓）：
  一名担当参与了某次训练，就给他**自己担当的演目** +1（槽未满时），哪怕他站的是别的训练位；
  外派卡、分身都按这条算。⇒ 速度位站着「担当在飞悬的角色」时，涨的是**飞悬槽**，流镝马这一位等于少一个推槽的人。
- **由此得到的推论（规划用）**：某演目某回合的槽增长 = 它的担当（1 名 NPC ＋ 它的若干张卡）里，
  当回合**恰好站在你点的那个训练位上**的人数。所以
  ① **卡被外派不损失槽**——只是它推的是**自己**演目的槽，且只在你点它所在那位时才推；
  ② 长期平均仍约 **1.2 人/回合**（NPC 随机到位的概率），与卡偏科无关（§2.2(b)④）；
  ③ NPC 站错位（站到别家）时，那份 +1 记给**他自己**的演目，不会给脚下那一位。
- **满槽不再吃加槽**：槽已满（=5，排练亮起）的演目不接收任何溢出（`frame*` 的
  `not_up_parameter_info.is_overflow_act_gauge_event_gain`），比赛 / 休息 / 事件的加点会自动落到**未满**的演目上。
  这一点可被主动利用，见 §3.5 末尾的「留一个弱演目满槽不点」。

## 3. 演目排练（演目稽古）

### 3.1 形态与规则

- 某演目槽满 → **对应训练变成演目排练**；**该位置此期间不能做普通训练**。
- **发动排练的那一回合，全部 5 个演目的槽都不涨**（`user` 2026-10-30）：排练占掉了这回合的训练行动，
  于是没有「训练」这个加槽来源；被排演目的槽在执行后清零，其余 4 个维持原值（不衰减也不增加）。
  **按行动算、不按回合冻结**——同回合改选普通训练就按 §2.3 照常涨，比赛 / 休息 / 外出也各归各行。
- **所有亮起位置**的各演目负责人（编组内担当卡 + 编组外担当 NPC + 吾妻补位）**锁定登场、不判不在率**
  （2026-10-31）：担当 NPC 与担当卡**必定出现在担当位置**，排练人数 = 担当数（可算）。
  不在率只作用于**未亮位置**的普通训练随机站位（U29）。**未亮位置**的担当卡 / NPC 仍按普通训练自由站位；
  **亮起但未执行的位置同样锁人**，亮起过多会减少其他位置的期望人头。
- **特定教诲可以给「分身」**（已定，`user` 2026-10-30）：牵绊（101，合宿中额外 1 人）、协助教诲、URA 限定的
  「排练编组卡各 +1 人」都会让**同一名担当在别的训练位上再出现一次**。数量、落点、持续时间与收益见 **§3.5**。
- **非担当 NPC 同框不算加槽人数**（已定，`user` 2026-10-30）：排练位上若站着「担当在别的演目」的 NPC，
  他**一个槽都不涨**——既不给正在排练的演目，也不给自己的担当演目（见 §2.3）。
- 效果构成：
  1. 基础值按**时期**取档（§3.2）；
  2. **基础能力额外 +10**（全 Lv 共通）；
  3. 吃友情加成、教诲（按参与人数叠加）；
  4. 编组类型 ≥5 时，另有 SP 排练效果 / 灵感事件 / Lv4+ 全灵感发动 / Lv4+ SP 上限 / Lv9+ 基础上限。
- 执行后：**演目Lv +1、槽清零**。
- **失败**：等同于训练失败，**会触发失败后事件**，不给属性收益；但 **演目 Lv 仍 +1**，**槽清零**（2026-10-31 确认）。
- **可延期**：亮起后不必立刻执行，不过期；**多个演目同时亮起可任选其一**，其余不消失。
- **合宿中的排练与普通排练是同一命令**（5101–5105），不是第三种训练类型。

### 3.2 基础值（`memo` 本轮新增，**按时期两档**）

顺序：速 / 耐 / 力 / 毅力 / 智力 / 技能Pt / 体力。

| 训练 | Junior 档                        | Classic 以后档                     |
| -- | ------------------------------- | ------------------------------- |
| 速度 | `16 / 0 / 3 / 0 / 0 / 9 / -25`  | `21 / 0 / 3 / 0 / 0 / 10 / -25` |
| 耐力 | `0 / 14 / 0 / 6 / 0 / 10 / -25` | `0 / 20 / 0 / 8 / 0 / 12 / -25` |
| 力量 | `0 / 6 / 14 / 0 / 0 / 10 / -25` | `0 / 8 / 20 / 0 / 0 / 12 / -25` |
| 毅力 | `3 / 0 / 2 / 15 / 0 / 10 / -25` | `3 / 0 / 2 / 23 / 0 / 12 / -25` |
| 智力 | `3 / 0 / 0 / 0 / 12 / 8 / +5`   | `4 / 0 / 0 / 0 / 14 / 9 / +5`   |

- **切换时点**：**Junior 12 月后半行动后的进度汇报会事件**（turn 23）——「演目排练强化」。  
  `memo` 明确：**成功与大成功都强化**。
- **与静态表的关系**：`single_mode_training_effect`（scenario 15）里 5101–5105 的值  
  （`16/0/3/0/0/9/-25` 等）**正好等于 Junior 档**；Classic 以后那一档静态表里没有单列。  
  即**排练基础值只按时期分两档、与训练Lv 无关**，静态表只记了第一档。**Senior 第三档暂定没有**（U02，未完全确定）。
  （`frame*` 的 `act_training_step` 局内 1 / 终局 2，疑似就是这个档位，语义未确认。）
- **不吃非擅长修正**（已定，`user` 2026-10-30）：上表的值与「该训练是不是擅长」**无关**，  
  没有 ×1.2 / ×0.8 这类修正，也不是「擅长才给满值」。排练只会按时期取档，再叠加下面列的加成项。

### 3.3 训练公式（`memo`，上段）

- **基础能力**：  
  `floor(下段 × (1 + 友情合计) × (1 + 训练效果合计) × (1 + 获得量合计)) − 下段`，  
  **演目排练再 +10**。
- **技能Pt**：  
  `floor(下段 × (1 + 友情合计) × (1 + 训练效果合计 + SP训练效果)) − 下段`。
- **友情合计**（仅友情训练时全部相加）：骏大祭加成、协助教诲、排练的演目Lv 效果、擅长率转成效果（排练）。  
  **前提是「彩圈」**：彩圈要角色站在**自己得意的训练类型**上才亮；**外派卡、分身站的是别的类型，通常没有彩圈**，所以它们一般吃不到友情，贡献走训练效果 / 获得量 / 面板。
- **训练效果合计**（全部相加）：助力教诲（非友情时）、助力支撑、兼修教诲（排练）、不屈教诲（排练）。
- **获得量合计**：主属性——特化教诲、牵绊教诲（排练）、牵绊转成（排练）；副属性——兼修教诲（**技能Pt 不吃**）。
- 教诲效果的 Lv 取**所绑定演目的 Lv**，与训练种类无关；效果只在该演目负责人**参与该训练**时生效，  
  且**按参与人数叠加**（例：助力演目有 2 名担当参与 → 助力效果 ×2）。
  **排练时「参与人数」= 担当数**：担当锁定登场、不判不在（§3.1），教诲给的分身落在别的训练位、不叠进排练位。
- **牵绊教诲的「牵绊 +3」按人数叠加**（`user` 2026-10-30）：点到的训练位上有 **N 名本演目的担当** →
  **全编组卡的羁绊 +3×N**，与上一条同口径。N 含**编组外 NPC 担当**与**分身**（§3.5）。
  注意「全编组卡」——**没站在那个位置上的卡也加**，是十种教诲里唯一惠及全队羁绊的一项；
  所以它是「全队养成收益」而非陪练收益：只要点训练时该演目担当在场，全卡组羁绊都在涨。
  （`memo` 教诲一览里写作「効果は重複しない」，以本条实测口径为准。）
- **下段**（已定，`user` 2026-10-30）：按惯例**沿用普通训练的下段**——同一训练位、同一训练Lv 的普通训练  
  基础值即为下段，排练不另起一套；上式的 `+10` 是排练专属的固定加项。
  **下层直接用基础库原始公式（`default_calc_training_value`）算普通训练值**；卡面 / 通用项都在下层。
  **剧本加成相关的数值全部体现在上层**（演目 Lv、教え、発表会 buff、稽古 +10 等），不重复计入下层已有项。
- **编组外的 NPC 只计人头数**（已定，`user` 2026-10-30）：`act_member` 那批嘉宾（5 名神驹 ＋ 带吾妻时的第 6 名）  
  在公式里**只作为人数**参与，不提供友情、训练效果、获得量这类支援卡加成。加成项只由**编组内的卡**产生。
- **NPC 不亮彩圈、不出叹号（Hint）**（已定，`user` 2026-10-30）：NPC 没有得意率（U22），也就**没有彩圈**；
  **不产生 Hint 事件、不贡献灵感**。⇒ ① 他**永远不可能是「2 闪彩」里的那一环**，只在那条「+1 人头」里起作用；
  ② 灵感 / Hint 类收益**完全与 NPC 无关**（与 §14.5「全灵感不含嘉宾」同向）。
- **吾妻要算面板**（已定，`user` 2026-10-30）：她是**友人卡**（第 6 位），训练效果、レスボ / スキボ、  
  绊 60 的スピボ＆スタボ 等**照常计入**她所在的训练位；**不参与职责分配**（§11.2），  
  面板**只按一张卡算一次**，不因在不同训练位出现而重复叠加。
- **实现约定**：AI 端一律按「带吾妻卡」建模，不做无友分支；即便不带卡，吾妻**仍在 turn 2 登场**  
  （剧情层面），差别只是少掉卡面板那一份（§11.2）。
- **NPC 没有得意率**（U22）：**普通训练时落位完全随机**，只有**演目排练**才锁在该演目对应的训练位（§2.2(b)）。
  因此排练的人数构成可算，普通训练里「哪几个人同框」只能按期望处理。

### 3.4 消耗与失败

- 体力消耗：排练 **-25**（智力排练 **+5**）；「体力教诲 / 转成」按百分比降低。
- 失败率：由**不屈教诲**（按剩余体力阈值）与**本番演出**（-100%）压制；Lv10 不屈与体力无关。
- **排练失败（2026-10-31）**：等同训练失败，会触发失败后事件、不给属性收益；但 **演目 Lv 仍 +1**；**槽清零**。

### 3.5 分身（教诲给的「额外登场」）

**一句话**：同一名担当**同时坐在多个训练位**上——本体留在自己的演目位，多出来的每一份都是「分身」，
分身**落到别的训练种类**、**强化那一处的训练**。

**数量 = 1 ＋ 每个「+1 人」效果**：

| 来源 | 加人 | 生效期 |
|---|---|---|
| URA 收尾期的限定效果（源自本番演出，§5.4） | 全部演目**各 +1 人** | turn 68–77（§7） |
| 协助（协力）教诲 | **+1 人** | 该教诲授予后（§4.2） |
| 牵绊（101） | **+1 人** | **合宿中**（§4.2） |

- **URA ＋ 协助 ⇒ 该演目担当共出现 3 处**：本体在演目位 ＋ 分身落在**另外两个训练种类**上
  （`memo`「教え効果も有効なので協力の教えと重複で3個所に出現」＋ `user` 2026-10-30）。
- **落点**：占**另一种训练种类**的位置、**不叠在排练位**（U36 ✓）。具体挑哪一处——
  `memo` 对协助教诲记的是「该演目**每个担当（卡+NPC）各额外 1 处登场**」，即**在非担当的训练位里随机**选一处；
  URA 那 +1 人沿用同一套机制。
- **排练位本身的人数不因分身变多**：分身落在**别的**训练位，排练的参与人数仍 = 担当数（本体）（§3.3）；
  分身的作用对象是**他落到的那个训练位**——在那里算一个完整参与者（U37 ✓）。
- **持续时间 = 该演目「排练激活」的整段时间**（已定，`user` 2026-10-30）：槽满亮起后**不执行就一直有效**，
  **每回合都在**（§3.1「可延期、不过期」，多个演目可同时亮起）；**执行排练后槽清零**，该演目的分身随之结束；
  想再要就得把这个槽重新攒满。
  前提是**当时身上有「+1 人」来源**（URA 限定 / 已授的协助教诲 / 合宿中的牵绊）——没有来源时，槽满也不出分身。
- **策略含义**（`user` 2026-10-30）：
  1. **URA 期**全部演目都带 +1 ⇒ 多个演目同时激活时，分身同时铺到多个训练位，训练效果**整体抬升**；
  2. **故意保留演目状态不点**（槽满但不执行排练），分身就**一直有效**、每回合都挂在别的训练位上，
     用其余 4 个位置的普通训练持续吃这份加成——这是「不点」的**主动收益**，不只是被动的垃圾桶盖；
     代价是**该位整段时间不能做普通训练**（§2.3），且**推迟了这次 演目Lv +1 / 槽清零**。
  3. **留一个「最弱的演目」满槽不点，当加槽的垃圾桶盖**（`user` 2026-10-30）：
     满槽的演目**不再接收任何加槽**（§2.3），所以生涯比赛的 **+4**、休息 / 事件的 +1 会**必定落到其他未满的演目**上，
     把排练节奏集中喂给主力演目。这个被牺牲的演目**只靠被动来源补 Lv**——合宿结束全演目 +1、吾妻外出「最低演目 +1」等，
     刚刚够过年底的 Lv 检查（Junior 3 / Classic 5 / 本番 6，§5），但**不点它的演目排练**，也就放弃了它的排练产出。

**分身的完整待遇**（已定，`user` 2026-10-30，U37 ✓）——分身 = **多出来的一个正常人物**：

| 项 | 待遇 |
|---|---|
| **加槽** | 同通用规则：给**他自己担当的演目** +1，**槽未满才加**（§2.3 的归集口径） |
| **卡效果** | **按完整值计入**他落到的那个训练位——训练效果、获得量、面板都算；**友情除外**：友情必须**彩圈**才算，而分身站的不是他自己的训练类型，**通常没有彩圈** ⇒ 一般吃不到友情加成 |
| **人数** | 计入该位的**参与人数**，因此教诲的「按人数叠乘」也把他算进去 |
| **Hint / 灵感** | 与本体**共享**：本体有叹号，分身也有叹号 |
| **羁绊** | 与本体**共享同一个计数器**：羁绊未满 100 时，**点本体或点分身都加同一份羁绊** |

- **分身在属性上是正常人物**（已定，`user` 2026-10-30）：所以**别的演目的分身**即使落到「正在排练的那个位置」，
  也**计入该排练的参与人数**（人数叠乘照算）。这与「非担当 NPC 同框不算加槽人数」（§3.1）是两回事——
  那条针对的是 NPC，NPC 不算分身。
- **实现约定（2026-10-30）**：分身**不新建人头**，在 `distribution` 中以**同一人头下标重复占位**；
  所有人数 / 加槽 / 卡效果按占位逐个计数、不去重；唯一不生效的是友情（非本职训练位不亮彩圈）。

### 4.1 传授、改派与槽位（`data` `single_mode_15_advice_recommend`）

| 时点（0 基） | 内容 |
|---|---|

**槽位模型（2026-10-31 澄清）**

- **永远只有 5 个教诲槽**（对应 5 个演目），不是「10 选 5」；追加 5 种教诲不是独立槽位，只作为融合对象。

- 改派窗口可以**保持不变**，不必强制重排；决定后到下一个窗口前不能改。
- 融合后：**被融合的基础教诲不再单独存在**（原基础教诲被消耗），由「升级版基础教诲 + 所绑定新教诲效果」占用该槽；
  未被融合的基础教诲保持不变。
- turn 23 融合的 2 个教诲到 turn 47 **不能再作为融合对象**（“不能动”），但仍参与 5 槽重排。
- 融合配对**不固定**：turn 23 是 2 个基础教诲 ↔ 特化 / 研钻 的 `2!` 配对；turn 47 是 3 个 ↔ 协助 / 不屈 / 兼修 的 `3!` 配对。
  玩家 / 训练员可以有预设的较优配对。
- 追加 5 种（`fusion_type = 2`）只作融合对象，不能当材料。

**决策空间（只用于实现估算）**

| 窗口 | 选择 | 组合数 |
|---|---|---|
| turn 2 | 5 个基础教诲分配到 5 演目 | `5! = 120` |
| turn 11 / 35 / 59 | 重排或保持 | `120 + 1`（保持原样） |
| turn 23 | 默认：融合配置固定，5 槽重排 | `5! = 120` |
| turn 47 | 默认：融合配置固定，5 槽重排 | `5! = 120` |

### 4.3 生效口径（实现时最容易错的三条）

1. **按绑定的演目取 Lv**，不是按当前训练的演目、也不是按教诲所在位置。
2. **只在该演目的负责人参与该训练时生效**，且**按参与人数叠加**（2 人 = 2 倍）；编组外神驹也算人数。
3. **牵绊 +3 的两点特殊**：同第 2 条**按人数叠加（+3×N）**；特殊之处在于① **作用于全编组卡**（不限于该训练位上的卡）② 吃「爱娇」补正、与训练本身的牵绊上升**分开加算**。它与该教诲在排练里的「主属性获得量 3–15%」是两个独立效果。

其他：

- 灵感教诲提升的是**该演目担当卡自身**的灵感发生率（`memo` 已核实）。
- **擅长率教诲对 NPC 不生效**（`user` 2026-10-30）：NPC 没有得意率（U22），擅长率对他无意义；
  该教诲只抬**编组内卡**的得意率。
- 演目效果 Lv4+ 的「全灵感发动」**不含嘉宾**（`memo` 已核实，与通用处理不同）。

### 4.4 追加排练（研钻教诲）

**发生率怎么算**

数据只有**一个数**：`effect_type = 8`（`extra_keiko_rate`，追加稽古发动率），Lv1→10 = **20 / 22 / 24 / 27 / 30 / 35 / 40 / 50 / 65 / 80**（%）。
游戏里没有第二张表参与这个判定，所以它就是一个**单次训练的触发概率**，按下面的方式合成：

```
p(该训练位) = min( 100%,  r(该演目Lv) × N )
  r = 上表的值（取「教诲所绑定的演目」的 Lv，不是当前训练的 Lv，§4.3）
  N = 站在这块训练位上的、属于该演目的担当人数
```

- **加算、不是独立重复掷**（`memo` 记「担当の人数分加算、上限 100%」）：N = 2、Lv10 时是 **min(100, 80×2) = 100%**，
  而不是 `1 − 0.2² = 96%`。差别只在 Lv 高又多人同框时才看得出来。
- **N 的构成**（按 §4.3 第 2 条 + §3.5，均已定）：**本演目的担当 NPC**、**外派到该位的本演目卡**、
  **落在该位的本演目分身**，三者都算人头；别的演目的角色**不算**。
  ⇒ 研钻是**唯一会因为「卡被外派 / 分身铺开」而在别的训练位开花的教诲**：担当在哪儿，追加稽古就在哪儿判定。
- **判定时机 = 回合开始预掷**：`memo` 记「アイコンが出ている場合、トレーニング後に発生」——
  图标在训练之前就已经显示，说明骰子在**这回合开始时**就掷好了，图标＝**掷中**。

## 6. 骏大祭合宿

- **共 3 次**，Junior 就有：turn 12–15 / 36–39 / 60–63（原始 13–16 / 37–40 / 61–64）。
- **每回合都是演目排练**，**不能做普通训练**（不是第三种训练，命令仍是 5101–5105）。
- 合宿中：**演目Lv 不升、演目槽不涨**；唯一例外是**目标比赛仍加槽**。
- **合宿结束后全演目Lv +1**，结算点**暂定为固定时点：该年 8 月后半结束**——
  即 **turn 15 / 39 / 63 结束时**（`user` 2026-10-30）。
  **固定 ≠ 跟着顺延走**：合宿遇目标赛 / 强制休息而延长时（如凯斯奇迹 turn 65 强制休息，导致 **Senior** 合宿从 60–63 延到 66），
  这 +1 **仍在 8 月后半（turn 63）结束时结算**，延出来的回合（64–66）发生在 +1 **之后**。
  ⇒ 实现上按**日历时点**触发，而不是按 `summer_camp_remain_turn_num == 0` 触发；后者只用来判断「本回合是否算合宿回合」。
  **延长回合属性（U18，2026-10-31）**：**所有年份的延长回合都算合宿（全部排练）**；
  第 1 年的延长回合也按第 1 年合宿规则（正常休息 / 可外出 / 可有支援卡事件）。
- **没有合宿内的体力回复事件**（与旧剧本不同）。
- **延长规则**（`user` 实测）：基础 4 回合；期间遇到目标比赛或强制休息，则把**后续正常回合改标为合宿回合**  
  （不产生额外回合），直到该年累计 **4 个非比赛合宿回合**；比赛 / 强制休息回合不计入。
- **事件**（已定，`user` 2026-10-30）：
  - **第 1 年（Junior，turn 12–15）合宿**：**支援卡连续事件** 与 **普通马娘固定事件** 都发生；
  - **第 2、3 年（Classic / Senior）合宿**：**常规 4 回合内两类事件都不发生**——不只是支援卡事件停了，  
    **普通马娘事件（固定角色事件）同样不发生**，常规合宿期在这两年是「纯排练 + 无事件」状态；
  - **延长段的固定事件仍然会发生**（已定，`user` 2026-10-30）：这是 `memo`「夏合宿中のウマ娘固定イベントは発生する」  
    的正确读法——它指的是**顺延出来的合宿回合里的固定事件**。  
    典型例：**凯斯奇迹在 turn 65 有固定休息事件（强制睡觉）**，该事件落在合宿期内，占掉一个合宿回合、  
    **不计入「4 个非比赛合宿回合」**，于是**合宿延长到 turn 66**；这个休息事件本身照常发生。  
    （因果方向要注意：是 **T65 的休息事件导致延长到 T66**，不是「比赛导致顺延到 T65」。）  
    与「第 2、3 年常规合宿无事件」不冲突：**常规回合抑制、延长回合的个体固定事件不抑制**。
  - **第 2、3 年合宿延长段是否触发支援卡连续事件 —— 待查（U19）**：  
    延长会把后续回合改标为合宿回合，若支援卡事件判定挂在「合宿回合」标记上，延长段就可能冒出本不该有的支援卡事件。
  - **实现口径（2026-10-30）**：**不复用引擎全局 `no_event_turns`**；剧本自持按年次 + 延长段的
    “不可发生连续事件回合表”，分别判定常规回合与延长回合。
- **休息**（`memo` + `user` 2026-10-30）：
  - **第一年（Junior，turn 12–15）合宿**：休息 = **普通休息**（随机抽选结果），**可以普通 / 友人外出**，
    也可有支援卡事件。
  - **第 2、3 年合宿**：**不能普通 / 友人外出**，休息 = **合宿版**（2026-10-31）。
- 产出参考：合宿回合中位 +145 vs 普通回合 +56，约 **2.59×**（964 份报文整体产出比，  
  **含休息与排练，不能当纯排练倍率**）。

## 7. URA 收尾期（turn 68–77）

- 本番后剧情结束，但**每回合仍是演目排练**。
